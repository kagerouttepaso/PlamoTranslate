# 変更を設計の幹に沿って進める

構造の崩れは、局所の修正が重なって生まれる。1つ1つの修正では見えず、気づいたときには大きな作り替えが要る。この手順は、変更のたびに構造を点検し、崩れを見つけたその変更の中で小さく直すためにある。設計の幹は `docs/設計/アーキテクチャ.md`「設計の原則」、触る機能の設計書の順に読む。

文言の修正のように設計に関わらない変更は、手順1で「局所」と判断し、手順4・7だけを行う。

## 1. 受け取る

- 要望を「望む状態」と「作者の案」に分けて作業メモに書く。作者の案は候補の1つとして、設計の幹・費用・リスクの同じ基準で自分の案と比べる。採否は作者が決める。
- 種類を決める：機能の追加／不具合／使い心地の調整／局所。

## 2. 仕組みを確かめる

- **不具合**：再現し、どの合図・状態・判定・データから起きたかを、コードとログで説明できるまで調べる。説明できる前に直さない。指摘された症状と同じ仕組みで起きる別の症状も挙げる。
- **機能**：設計書の差し込み口（画面翻訳は `docs/設計/画面翻訳.md`「将来の機能の差し込み口」）で、差す場所を決める。
- **端末やOSの振る舞いに依存する**：推測で作らない。`docs/資料/端末の能力.md` に無ければ、`featurelab` で単体で確かめてから設計する。

## 3. 構造を点検する

直す場所を見て、次のどれかに当たれば、変更の前に構造を直す。

| 合図 | 起きていること | 直し方の向き |
| --- | --- | --- |
| 例外の判定・フラグ・定数を足さないと直せない | 判断が置き場を持っていない | 判定器か状態遷移に、名前のある判断として置く |
| 「いつ何をするか」を状態遷移の外で決めている | 制御が散り始めた | 出来事として状態遷移へ渡し、作業として返させる |
| 判断が Android の側（サービス・画面）にある | 中核で試せない判断が増えた | 中核（`core-pipeline`）へ移し、単体テストを書く |
| 翻訳を `TranslationStream` の外で呼ぶ | 契約が2本になり始めた | 契約の命令と購読で通す |
| 差し込み口が無い | 設計がこの種類の変更を想定していない | 先に設計書に差し込み口を決める |
| `tools/check-design.ps1` の注意（大きいファイル、何度も変わるファイル） | 責務が集まり、局所修正が重なっている | その部品の責務を分けられるかを見る |

構造の直しは、変更の目的とは別のコミットにする。モジュールや翻訳の契約を変えるほどの直しは、`docs/作業中/` に短い計画（望む状態、今の構造の問題、直した後の構造、移す順番）を書き、作者の合意を取ってから進める。

## 4. 実装する

- 1つの目的を1つのコミットにする（構造の直し、機能、不具合の修正を混ぜない）。
- 判断は中核に置き、単体テストを書く（`.\gradlew.bat :core-pipeline:test`）。
- 不具合の修正には、その仕組みで起きることを確かめる試験を足す。
- 共通の部品や契約（`TranslationStream` など）に新しい呼び出し側を足すとき、また機能を共通の部品へ移すときは、その呼び出し側が渡す入力の形（複数行、空、長文、同じ文の重なり）を契約の単体テストに足す。部品が前提にする入力の形は、入力を受け取る1か所で守らせ、設計書に書く。

## 5. 点検する

- `pwsh -NoProfile -File tools/check-design.ps1` を回し、誤りを直す。注意は手順3の表で判断する。
- 中核・状態遷移・翻訳の契約・差し込み口に触れた変更は、`design-reviewer` エージェントに差分の範囲（例：`git diff HEAD~3`）を渡して読ませる。書いた意図は渡さない。返った指摘を直すか、直さない理由を作者への報告に書く。

## 6. 実機で確かめる

作者に確かめてもらう点を、「何をすると、何が起きるはず」の形で具体的に渡す。端末で確かめられない変更は、確かめていないと報告する。

## 7. 文書を直す

`docs-update` スキルの手順で、設計書・判断の記録・現在地・バックログを直す。不具合や指摘から来た変更は、手順2で特定した構造と、手順3で一般化した先を判断の記録に残す。

## リリースの前

イテレーションの終わり（版を上げる前）に、前の版のタグからの差分を `design-reviewer` に読ませる。直すべき崩れはこの版で直すか、`docs/バックログ.md` の「リファクタリング」に理由と一緒に置く。崩れを次の版へ黙って持ち越さない。
