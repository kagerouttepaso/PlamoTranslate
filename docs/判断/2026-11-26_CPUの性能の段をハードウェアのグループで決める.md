# CPU の性能の段をハードウェアのグループで決める

- 状態：有効
- 問題：Xiaomi 15T Pro では、同じクラスターの CPU 4〜6 の `cpu_capacity` が動作中に 871 と 880 の間で変動した。値の一致で段を決めると同じクラスターが分かれ、値を保存鍵に含めると次の起動で翻訳の試走をやり直した。
- 決めたこと：Android は cpufreq ポリシーを1段とし、最高周波数で並べる。Windows は性能クラスを1段とする。翻訳と Qwen3-ASR は、速い段から順に各段の CPU 番号を並べた v2 の鍵で保存結果を照合する。
- 理由：試走の候補を決めるのは、呼び出したスレッドで使える CPU の番号と各段の構成である。同じ構成で保存結果を再利用でき、許された CPU や段の順位が変われば再試走できる。
- 再発を防ぐもの：`ComputeSchedulerTest` で、所属内の値の変動、同速の別グループ、一部の CPU だけを許された場合、所属を取得できない場合の段と候補を確かめる。貸出時には各段に含まれる CPU 番号を速い段から順に記録する。
