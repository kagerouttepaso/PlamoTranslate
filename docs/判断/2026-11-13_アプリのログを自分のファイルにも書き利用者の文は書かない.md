# アプリのログを自分のファイルにも書き利用者の文は書かない

- 状態：有効
- 問題：不具合の記録に、取り込んだ時点の logcat の写しを添えていたが、REDMAGIC は既定で `log.tag=S` で、アプリのログも `AndroidRuntime` も書かれない。端末を再起動した後に落ちると、写しはほぼ空になる。写しはどのプロセスの行かを記録と結び付けられず、一番新しい終わり方にしか添えられなかった。会話翻訳は原文と訳を `Log.i` に出していて、ログを開けた端末では書き出した記録に入った。設計レビューで指摘を受け、作者が計画（全モジュールのログを1つの出口に通し、アプリのファイルにも書く。正式版では利用者の文を書かない）に合意した。
- 決めたこと：ログの出口のモジュール `core-log`（`Logs`・`LogSink`）を足し、`app`・`core-llm`（ネイティブを含む）・`core-ocr`・`core-tts` のログをすべて通す。書き先は `app` が差し、logcat とプロセスごとのファイル（`files/logs/<プロセスの鍵>.log`、256KB で1つ前の分を残して書き直す）に書く。次の起動で、同じ鍵のファイルを記録に添え、OS の記録で終わり方を見たプロセスのファイルだけを消す（まだ出ていない終わり方のログは3件まで残す）。利用者の文を含む行は `Logs.text` で渡し、正式版では書かない。`tools/check-design.ps1` が、出口を通らない logcat への書き込みを止める。
- 理由：端末に依らず、落ちたプロセスの最後の行までを、その記録に結び付けて残せる。ファイルへは1行ごとに OS へ渡すので、ネイティブの落ち方や SIGKILL でも渡した分は残る。実機で、`log.tag.PlamoTranslate` を黙らせた状態で例外で落とし、記録に、ネイティブ（llama.cpp）の行と落ちる直前の例外の行を含むログが入ったことを確かめた。利用者の文は不具合を調べるのに要ることが少なく、要るときはデバッグ版で再現して見られる。書き出したファイルを人に渡しても、会話や画面の文が漏れない。
- 捨てた案：logcat の写しのままにする（REDMAGIC の既定で空になる）。落ちたときだけ書く（ネイティブの落ち方と OS に止められたときは、プロセスの中で受け止められない）。各エンジンに書き先を引数で渡す（呼ぶ側の書き換えが広く、渡し忘れを点検で止められない）。ネイティブから同じファイルへ直接書く（Kotlin 側の大きさの管理と二重になる）。
- 再発を防ぐもの：`tools/check-design.ps1` の約束4（ログの出口）。`LogsTest`（利用者の文を正式版で書かない）、`ProcessLogFileTest`（行ごとに残る、上限での書き直し、片付け）、`CrashJournalsTest`（ファイルの規則）。`docs/設計/アーキテクチャ.md`「ログ」。
