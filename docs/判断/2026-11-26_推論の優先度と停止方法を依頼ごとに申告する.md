# 推論の優先度と停止方法を依頼ごとに申告する

- 状態：有効
- 問題：許された CPU が4個の端末で途中の書き起こしが4個を7.3秒占有し、言語の識別は7.28秒待った。数の合計を制限しても、取り消せる依頼が高い優先度の処理を待たせていた。
- 決めたこと：各依頼は優先度、止め方、スレッド数の変更に再読み込みが要るかを申告する。自動設定では共通の試走で、最速との差が反復計測のばらつきに収まる最小の数を選ぶ。割り当てと横取りはプロセスのスケジューラーで決める。
- 理由：同じ認識器でも、途中結果は捨てられ、確定結果は利用者に返す必要がある。読み上げは表示した訳を利用者の操作で音にする処理なので、訳や OCR と同じ Normal に置く。機能固有の時間やコア数を優先度の根拠にすると、端末や入力が変わるたびに調整が要る。
- 再発を防ぐもの：`ComputeSchedulerTest` は横取り・区切り・再開順・貸出数、`ThreadTrialsTest` は反復のばらつきと CPU の組を含む保存条件を確かめる。実機では貸出と横取りのログで、識別の待ち時間と途中結果の返却までの時間を区別する。
