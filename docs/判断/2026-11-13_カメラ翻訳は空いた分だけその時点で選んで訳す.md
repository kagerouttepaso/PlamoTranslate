# カメラ翻訳は空いた分だけその時点で選んで訳す

- 状態：有効
- 問題：カメラ翻訳で一時停止した後、見えている20件ほどの訳がそろうまで数十秒待たされた（作者の指摘「そんなふうに作った覚えはない」）。実機（REDMAGIC 11 Pro、0.8B、CPU だけ、同時に訳す数4）のログでは、エンジンが1回で67件を訳し（25秒）、1件ごとの「頼んでから確定まで」が頼んだ順に1.2秒から21秒まで伸びた。読み取りがそろった段落を全部、頼んだ順に流れへ渡していて、画面の外へ出た文を取り消さず、読み揺れで少し違って読めた同じ段落を別の文として頼み直していた（訳がまだ1文字も出ていない文とは「ほぼ同じ」の照合が効かなかった）。一時停止の「見えている文を先に」は、流れに渡す前の一覧を並べ替えるだけで、渡し済みの文の後ろに付いた（2026-11-12に「4段落ずつ頼む」から「頼んだ順にすぐ訳す」へ変えたときに入った）。
- 決めたこと：作者と合意した計画（あるべき姿から作り直す、段階1）で、翻訳の流れに渡しておく文を、流れが無駄なく訳せる数（`intakeFor`。1件ずつのコアは行をつないで訳すので8件、同時に訳すコアは同時に訳す数。コアの事情なので翻訳の側で決める）までにとどめ、空きが出るたびに、その時点で見えている段落から画面の中央に近いものを選んで渡す。訳は段落の番号（行の番号から受け継ぐ「もの」の名前）に結び付け、渡している段落は原文が変わっても確定まで渡し直さず、ほかの段落でほぼ同じ文を渡していれば渡さない。一時停止は読むのを止めるだけにし、訳し方は変えない。空きが残れば、読み取りがそろっていない段落も訳す（実機で、読み揺れが収まらない段落やつながるかどうかが揺れる段落が、流れが空いているのにいつまでも訳されず、作者の指摘を受けて、計画の段階1に先読みを含めた）。判断と制御（設定の変更で何を捨て、流れを開き直すかを含む）は中核の `CameraSession`（`pipeline.camera`）に移し、`LiveTranslator` は外とつなぐだけにした。追った行の読み取りの履歴を持つので、制御は純粋な関数ではなく、状態を持つ `handle` にした。
- 理由：深い待ち行列を作ってから優先度を入れ替える形では、見えなくなった文や古い読み取りが行列に溜まることが変わらず、並べ替えの規則が翻訳の流れ（契約）とカメラ翻訳の両方に散る。並んで待つ文を作らなければ、選ぶ瞬間の状態がそのまま優先度になり、並べ替えも取り消しも要らない。無駄に訳すのは、見えなくなったときに訳している途中の、最大で同時に訳す数の分だけになる。翻訳の契約は変えずに済む（`submit` だけを使う）。渡しておく数を同時に訳す数で決めると、1件ずつのコアが行をつないで訳す仕組みが働かず遅くなるので、コアの選び方と同じ所（`intakeFor`）で決めた（設計レビューの指摘）。
- 捨てた案：翻訳の流れに優先度と並べ替えを足す（上の理由）。今の作りに取り消しと重複の判定だけを足す（訳が文字列に結び付いたままで、読み揺れのたびに頼み直しと取り消しが続く）。
- 再発を防ぐもの：`CameraSessionTest`（空いた分だけ渡す、読み揺れで頼み直さない、見えていない段落を渡さない、中央に近い順、一時停止）。ログの「一時停止から見えている訳がそろうまで」。`docs/設計/カメラ翻訳.md`「翻訳」「制御」。
