# 正本を1つにし不具合はその段の規則で直しモジュールの依存を表で検査する

- 状態：有効
- 問題：同じ語彙・作り方を持つブラウザー拡張版で、表示の崩れを要素ごとに直しかけ、根本の原因（流れの途中の段の規則の欠け）を後から直した。このリポジトリでも、設計の原則に「正本を1つにする」「不具合をどの段で直すか」が書かれておらず、モジュールの依存の向きは文章で決めているだけで、ビルドは表に無い依存（例：`core-ocr` から `core-llm`）を止めない。コメントには、文書を分ける前の番号（docs/ の下の2桁の番号）を指す参照が残っていて、検査が見逃していた
- 決めたこと：
  - `docs/設計/アーキテクチャ.md`「設計の原則」に、正本を1つにすること（DRY）と、不具合はデータと制御の流れのどの段の規則が破れたかを特定してその段で直すことを足す。`CLAUDE.md`「不具合」も同じ言い方にそろえる
  - モジュールの依存を「層とモジュール」の表に書き、`tools/check-design.ps1` がその表と各 `build.gradle.kts` の `project(...)` を照らす。表を正本にし、スクリプトに一覧を書き写さない
  - `tools/check-docs.ps1` は、`.md` を書かずに節を付けた `docs/` の参照も、行き先が無ければ誤りにする
- 理由：作者の方針（DRY・SOLID、症状でなく流れの中で直す）。2か所に書いた決まりは片方だけが直されて食い違うので、文書を正本にして検査が読む形にすると、決まりを変えるときに文書と検査が同時に変わる
- 捨てた案：依存の決まりを Gradle の設定（プラグインや設定の検査）で持つ（Gradle の設定と文書の2か所になり、ビルドの設定も重くなる）
- 再発を防ぐもの：`docs/設計/アーキテクチャ.md`「設計の原則」の7・8と「層とモジュール」の表、`tools/check-design.ps1` の約束5、`tools/check-docs.ps1` の参照の検査（pre-commit と Stop フックで回る）
