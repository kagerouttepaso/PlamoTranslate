# 訳の枠を1つの窓にまとめる

- 状態：有効
- 問題：韓国語の飲食店のメニュー（訳す単位が数十ある画面）を、0.8B・開始は自動・漫画のプリセット・言語は自動で画面翻訳にかけると、必ずアプリが終わった。OS の記録は「自分で終了コード0で終わった」で、例外も落ち方の記録も無かった。終わる瞬間の呼び出し元を一時的な仕掛けで捕まえると、Android の `WindowManagerGlobal.addView` が `System.exit(0)` を呼んでいて、呼び出し元は訳の枠を出す `TranslationOverlay.show` だった。端末の `framework.jar` を読むと、nubia が足した `checkAppShouldExit` が、1つのプロセスの窓が60を超えると終わらせていた。訳の枠は1つにつき窓を1つ置いていたので、単位の多い画面では枠だけで数十の窓になり、訳し直しで外した前の窓（片付けが後になる）と重なって60を超えた。開始が自動で、取り消しと訳し直しを繰り返していたことも重なりを増やした。
- 決めたこと：訳の枠を全部、枠全体を囲む長方形の1つの触れない窓（`FLAG_NOT_TOUCHABLE`）の中に並べる。窓は枠を出すときに置き、撮る前と取り消しで外す。画面全体にしないのは、ほかのアプリから見て「覆われている」印の付く範囲を、枠のある所までにとどめるため（覆われた操作を捨てるアプリでは、その範囲の操作が届かない。リリースの前の設計レビューの指摘）。ふつうの重ね表示では窓の不透明度を通り抜けの上限（0.8）に、ユーザー補助の重ね表示では1にする。
- 理由：原因は窓の数が枠の数に比例する作りで、1つにまとめれば枠がいくつあっても窓は増えない。前は「全画面の窓だと下のアプリを操作できない」として小さな窓にしていたが、それは枠に触れると反応した頃の前提で、触れない窓は全画面でも不透明度が上限以下なら操作を通すことを featurelab で確かめた（`docs/資料/端末の能力.md`「重ね表示と触れた操作」）。作者の端末で、同じメニューを同じ設定でかけても終わらなくなった。
- 捨てた案：枠の数を60未満に抑える（端末の決まりの値に合わせた定数で症状を抑えるだけで、上限の違う端末や、ほかの窓と合わせた数では外れる。訳を出せない単位も出る）。外した窓の片付けを待ってから足す（重なりは減るが、1ページの枠が60を超える画面では終わる）。
- 再発を防ぐもの：`TranslationOverlay` の説明と `docs/設計/画面翻訳.md`「訳文の重ね表示」に、窓を1つにする理由を置いた。REDMAGIC の決まりは `docs/資料/端末の能力.md`「設計に効く、思わぬ事実」。
