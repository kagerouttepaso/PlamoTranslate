# 話し中の言語の見張りを途中結果の間隔から切り離す

- 状態：有効
- 問題：0.11.0-beta.1 の作者の会話で、間を空けずに話し手が代わっても、カードが確定する前に区切られなかった。2つの記録で、話し中の言語の判定は中央1.2〜1.8秒、遅いと3.4〜3.7秒おきで、判定1回は0.15秒ほど（最大0.32秒）だった。見張りを途中結果と同じ時に頼んでいたので、途中結果の間隔（書き起こしにかかった時間の2〜3倍）に引きずられていた。判定の約4割は判定できない窓なので、違う言語が3回届くまでに新しい話し手が8秒ほど話す必要があり、短い発話では区切らずに終わった。区切ると決めても、継ぎ目を探す範囲（3.5秒前〜1秒前）より前に交代があると、新しい話し手の頭が前のカードに残る。
- 決めたこと：見張りは、話した音声0.5秒ごとに、途中結果とは別に数えて頼む。続けて3回違えば区切る決まりは変えない。
- 理由：途中結果の間隔を延ばすのは書き起こしの CPU を確定に回すためで、別の担当（言語の識別）で動く軽い判定まで遅らせる理由は無い。軽い仕事の間隔を、重い仕事の間隔に結びつけない。
- 再発を防ぐもの：`SpeechSegmenterTest` の「書き起こしが重く途中結果の間隔が延びても話し中の交代にすぐ気づき継ぎ目で区切る」。試験の時計は渡した音声の長さで進め、書き起こしの遅れが途中結果の間隔に効くようにした。
- 残る見込み：判定の窓が1.5秒と短く、判定できない窓が多い。0.11.0-beta.2 の記録で、区切りの遅れと外来語での誤った区切りを確かめる。
