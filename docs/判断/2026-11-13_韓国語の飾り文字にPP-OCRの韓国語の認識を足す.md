# 韓国語の飾り文字にPP-OCRの韓国語の認識を足す

- 状態：有効
- 問題：韓国語の指定では ML Kit 韓国語1つに頼っていて、縁取りや色の付いた飾り文字のハングル（トリッカルのメニュー「업적」「전투」「모집」やロゴ）を読めないか崩した（「전투」→「전}」）。認識器が4か所に名前で決め打ちされ、足すには分岐が要った。
- 決めたこと：作者の決定で、原文の言語を韓国語にしたとき、PP-OCR の検出（漫画用の det）と `korean_PP-OCRv5_mobile_rec` の認識を ML Kit 韓国語と並べて動かす。ハングルの行は PP-OCR 韓国語を先に採り、空白を除いて同じ文字なら空白を保つ ML Kit を採る。確信度0.8未満の行は採らない。モデルは初回にそろえる組に入れる。自動の指定には入れない。
- 理由：PCでトリッカルの画面1枚（`tools/ocr-spike.py --model korean`）を読ませると、ML Kit が読めなかった・崩した文字を確信度0.89〜1.00で読め、ロゴの下段「대폭망의도시!」も読めた。外れは画素画の飾り（確信度0.16）とロゴの1字の抜けだけだった。モデルは公式が Paddle 形式だけなので、公式の重み（コミット `c02ecaf1`）を PC で ONNX に変換したものと、公開されている変換済みの版（`mxaln/docscanner-ocr`）の出力が一致する（差は最大1e-6）ことを確かめて後者を固定した。自動に入れると中国語・日本語の行の選び方にも効くが、手元に評価の画面が無く前後を比べられない。
- 捨てた案：Paddle 形式のモデルを自前で ONNX にしてGitHubのリリースに置く（公開の手間が増え、中身は同じ）。読んだ範囲を拡大して ML Kit で読み直す（ロゴのように見つからない文字には効かない）。
- 再発を防ぐもの：認識器は、読み手1つと `Source`・`Recognizers`・`ChoicePolicy`・`PaddleModels` への1行で足し、ほかの引数や分岐を変えない（`docs/設計/画面翻訳.md`「読む流れ」、`ChoicePolicyTest` が表への足し忘れを止める）。行をどう採るかは読み手の名前でなく方針の表で決める（`LineChoiceTest`）。
