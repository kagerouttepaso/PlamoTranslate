# 会話翻訳の長い発話は文の終わりで区切り話し終わりの間を3秒にする

- 状態：有効
- 問題：会話翻訳の区切りを、既知の不具合（言語の誤判定による区切り、語尾・語頭の欠け）が減ったかだけで比べていて、カードが適切な粒度になっているかを測っていなかった（作者の指摘「視座が下がっていないか」）。長い発話は14秒で音の静かなところだけを見て切り、文の途中で切れていた。考える間（2秒）でもまとまりの途中が切れ、区切るボタンができた後も、作者は自動の区切りをもっと粘らせたいと求めた。
- 決めたこと：カードの粒度の目標を作者と決めた（1枚は話した人の1〜2文、文の途中で切らない、対面の面で読める長さ、断片を作らない）。正解に合わせ込むのではなく、細切れにしないことが目標で、話した人が間を置いて切れたのは許す（作者が確かめた）。録音に正解のまとまりを付け、`tools/score-conv.py` で採点するようにした。そのうえで、長い発話は、認識結果の句読点の時刻（SenseVoice が句読点にも時刻を付けることを端末で確かめた）から、直近6秒の一番後ろの文の終わり（無ければ読点）で切り、無ければこれまでどおり静かなところで切る（`CutPoint.longUtterance`）。話し終わりとみなす無音を3秒にした。
- 理由：作者の会話の録音（約5分、正解のまとまり22）で次のとおりになった。自動の判断で文の途中を切った数は、元の版4、言語の判定を厳しくした版3、この版2。断片のカードは5→3→1、切れ目の近くで消えた文字は39→25→16。カードは中央24文字・最大63文字で、読める長さ（90文字）に収まった。まとまりが1枚になる数は4→6→9に増えたが、読める長さに収まっているので許す。確定訳は無音が1秒延びた分だけ遅れる（区切るボタンで早く確定できる）。
- 捨てた案：長い発話を直近の文の終わり（VADの区切り）や0.3秒続いた静かさで切る（文の途中の息継ぎでも切り、文の途中の区切りは減らなかった）。文の切れ目が見えるまで最大5秒切らずに待つ（録音で文の途中の区切りが減らず、処理が増えるだけだった）。考える間で切れたカードを後からつなぐ（処理が複雑になり、作者も求めていない）。
- 再発を防ぐもの：`tools/score-conv.py` と正解（`tools/testdata/conversation/`、Git に入れない）、`CutPointTest`（文の終わりを読点より先に使う、切れ目の時刻の後ろの間にそろえる）、`AsrTest`（句読点の時刻から切れ目を作る）。`docs/設計/会話翻訳.md`「カードの区切り方」「動作確認」。
