# 書き起こしのGPU候補だけを翻訳モデルのGPU準備と直列にする

- 状態：有効
- 問題：REDMAGIC 11 Pro でアプリを停止してから会話翻訳を開くと、書き起こしの準備に20.0秒かかった。自動選択で保存済みの CPU（6/6/6 スレッド）を使う場合も、翻訳モデルの GPU 準備が終わるまで書き起こしの読み込みが待たされた。
- 決めたこと：Android と Windows で、GPU 候補を試すときだけ翻訳モデルと共通の準備ロックを取る。GPU の準備開始の記録、読み込み、試走、終了の記録を同じロックの中で行う。
- 理由：翻訳モデル（PLaMo 2B Q4_K_M、OpenCL）の読み込みに7秒、初回推論に5秒かかり、その後に Qwen3-ASR の CPU での読み込みが約7秒、ならしが0.5秒続いた。CPU の書き起こしと GPU の翻訳が同時でも結果が一致することは[同じ GPU の推論を直列にする判断](2026-11-24_Qwen3-ASRの途中認識を中断し翻訳と同じGPUの推論を直列にする.md)で確認している。
- 捨てた案：各 OS が保存済みの選択を読み、準備全体をロックするかを決めると、候補を選ぶ判断が重複し、初回の自動選択では CPU 候補の計測まで待たされる。
- 再発を防ぐもの：`TranscriptionTunerTest` は CPU と GPU の各候補の読み込み・試走でロックの有無を確かめる。GPU の障害記録と取り消しの後はロックが解放されることも確かめる。
