# カメラ翻訳の区切りと原文を直近のコマの多数決で安定させる

- 状態：有効
- 問題：段階1（空いた分だけその時点で選んで訳す）の後、作者から、読み取りのロバスト性について一般に知られた手法を取り込み、現地で文字を読む場面では電池より安定性・精度・速さを優先するよう、計画の立て直しを頼まれた（作者と合意した作り直しの計画。残りは `docs/バックログ.md`「使ってから決める」のカメラ翻訳）。段落のまとめ方をコマごとに作り直していて、境目の行が付いたり離れたりし、段落の原文が変わって訳し直しと枠のちらつきが起きていた（作者の指摘「つながるかつながらないか微妙な文字」）。原文は8回の読み取りから1つを選ぶだけで、読み続けても1回分より良い文にならなかった。
- 決めたこと：段落の区切り全体を状態として持ち、今の段落ごとに、そのコマのまとめ方と顔ぶれが違ったコマを直近6コマで数え、6割を超え3コマ以上になった段落だけを、そのコマのまとめ方の段落で置き換える（`StableGrouping`）。原文は、ほかといちばん似ている読み取りを土台に、各読み取りを編集距離で並べて位置ごとに多数決する（`ReadingFusion`。3回以上読めたとき、奇数回分）。互いに一致しない読み取りでも、多数決の得票の割合が0.75以上なら読み取りがそろったとみなす（`Track.settled`）。段落の訳し直しの数をログに出して、実機で前後を比べる。
- 理由：動画の文字認識で、区切りの決定を時間方向に平滑化するのと、複数フレームの読み取りを文字単位で統合する（音声認識の ROVER と同じ）のは、どちらも一般的な手法で、費用が小さく中核の単体テストで確かめられる。1コマの揺れで区切りを変えなければ、段落の原文が落ち着き、訳し直しと表示のちらつきが減る。文字ごとの多数決は、1回1回が崩れていても正しい文に近づく。実機（REDMAGIC 11 Pro、0.8B）で作者が使い、区切りの付いたり離れたりが大きく減り、安定感が増したと確かめた（「かなり改善されてる」）。パッケージのロゴのような飾り文字では、付いたり離れたりが続くことがまだあるが、許せる程度だった。そのときのログの訳し直しは、渡した45件のうち15件、76件のうち11件、8件のうち0件（訳し直しには、読み続けて原文が正しくなった分と段落の伸びも含む。段階1の数は取っていないので前後は比べていない）。
- 捨てた案：行の組ごとに「つながった・離れた」を数え、つながっている組を結んで段落にする（最初に作った形。設計のレビューで、結ぶと前の段落と新しい段落がつながって、まとめ方の行数の上限や表・メニューの2行までの約束を超える段落ができること、付くのと離れるので切り替わりやすさが違うことが分かった）。まとめ方の規則（行の間隔のしきい値）を緩める・締める（境目の行の揺れは、どのしきい値でも境目の近くで起きる）。1つを選ぶ方式のまま読み取りの数を増やす（1回分より良い文にはならない）。
- 再発を防ぐもの：`StabilityTest`（崩れた読み取りが混じっても正しい文になる、境目の行が1〜2コマ揺れても段落が変わらない、はっきり離れたら切り替える、切り替えた段落はそのコマのまとめ方の段落になる）、`CameraSessionTest`「境目の行が付いたり離れたりしても段落を訳し直さない」。`docs/設計/カメラ翻訳.md`「追跡と多数決」「段落にまとめる」。
