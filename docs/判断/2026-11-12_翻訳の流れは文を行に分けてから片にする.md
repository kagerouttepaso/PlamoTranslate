# 翻訳の流れは文を行に分けてから片にする

- 状態：有効
- 問題：0.7.0 の公開前の設計のレビューで、テキスト翻訳の複数行の訳が1行目で切れ、長い文を分けたときに行の区切りが消えることが分かった。翻訳の流れ（`TranslationStream`）は「片は1行」を前提に、依頼の行と訳の行を対応させている（逐次のコアのつなぎ方、生成の打ち切りの行数、途中の訳の行送り）。この前提を、文を受け取る入口で守らせていなかった。画面・カメラ・会話の原文には改行が入らないので表に出ず、テキスト翻訳を流れへ移したとき（入力の全体を1つの文として頼む）に初めて複数行の文が入った。移すときの試験は、テキスト翻訳が渡す入力の形を含んでいなかった。
- 決めたこと：文を片にする1か所（`TranslationStream.drainInbox`）で、まず改行で行に分け、行ごとに片にする。片の訳は行の中で `joinPieces` でつなぎ、行どうしは元の改行でつなぐ（`Seg.lines`・`assemble`）。
- 理由：前提を入口で1回守らせれば、行を数える3か所（コアのつなぎ方、打ち切り、途中の訳）を個別に直さずに済む。打ち切りに渡す行数だけを直すと、改行の消失と途中の訳の行送りが残る。
- 捨てた案：テキスト翻訳の側で行に分けて複数の文として頼む。呼び出し側ごとに前提を守らせることになり、次の呼び出し側で同じことが起きる。
- 再発を防ぐもの：
  - 試験：`TranslationStreamTest`「複数行の文は全部の行を訳し改行を残す」「長い行を分けて訳しても行の区切りは残る」（同時に訳す数1と4）。
  - 設計：`docs/設計/翻訳コア.md`「片とコア」に「片は改行を含まない」と、その前提に立つ処理を書いた。
  - 手順：`.claude/skills/change-flow` の手順4に「共通の部品や契約に新しい呼び出し側を足すときは、その呼び出し側が渡す入力の形を契約の単体テストに足す。前提にする入力の形は入力を受け取る1か所で守らせる」を足した。
  - リリースの前に前の版からの差分を設計のレビューの担当に読ませる流れ（`docs/判断/2026-11-12_変更のたびに構造を点検し小さく直す.md`）が、この不具合を見つけた。
