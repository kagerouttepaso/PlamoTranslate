# PCの会話画面は取り込み前に使う認識器を準備する

- 状態：有効
- 問題：PC では音声入力の開始を押すまで認識器を読まず、再生音の SenseVoice は自動判定用を開いてから最初の書き起こしで言語固定用を追加していた。カードの時間には発話中の認識が含まれず、遅れの場所も分かりにくかった。
- 決めたこと：Android の会話画面と同じく、音声翻訳画面を開くと認識器を準備し、開始を押したら同じ読み込みを待つ。言語が固定された再生音では、SenseVoice をその言語で準備する。カードには計測区間の名前を出す。
- 理由：同じ合成音声で、再生音の最初の書き起こしと開始操作から取り込みまでの待ちが短くなった。区切りの無音と、自動判定のために声をためる長さは中核の共通設定である。実測は `docs/設計/会話翻訳.md`「性能の目安」。
- 捨てた案：Qwen3-ASR の既定を Android と同じ6スレッドにする。4コアの PC で4・6スレッドを比べると、確定訳の早かった設定は回によって変わった。
- 再発を防ぐもの：`AudioPresenterTest` が、準備と開始が重なったときの読み込み回数、識別モデルが届いた後の準備、再生音の言語が準備時と認識時で一致することを確かめる。
