# 画面翻訳の原文の言語を言語で持ち読める言語をすべて選べるようにする

- 状態：有効
- 問題：画面翻訳は原文の言語を認識器の組（`OcrLanguage`）で持っていたので、同じ認識器で読む別の言語を指定できなかった。ラテン文字で書くフランス語・スペイン語などの画面で「英語」を選ぶと翻訳に `en` が渡り、繁体字は `zh-hans` として渡った。カメラ翻訳は、すでに言語（`Language`）で持っていた（[2026-11-08_カメラ翻訳の原文と訳す先の言語を広げる.md](2026-11-08_カメラ翻訳の原文と訳す先の言語を広げる.md)）。「読める文字で選べる言語が決まる」という同じ事情を、2つの機能が別の型と別の表で持っていた。作者の要望は、今の文字認識で読める言語を指定できること。
- 決めたこと：画面翻訳も原文の言語を `Language` で持ち、動かす認識器の組は言語から決める。言語と認識器の組の表、保存値の読み書きは、カメラ翻訳と画面翻訳で共通の1つ（`overlay/SourceLanguages.kt`）にする。メニューの行には自動・中国語・韓国語・英語を残し、ほかの読める言語は「他の言語」を押して開くサブメニューに並べる。サブメニューの言語を選んでも「他の言語」の名前は替えず、選択中の表示にする。自動で動かす認識器は変えない。
- 理由：選べる言語は文字認識が読める文字で決まり、この事情はカメラ翻訳と同じ。サブメニューに分けるのと名前を替えないのは作者の決定（メニューが縦に長くなる・崩れるのを避ける）。行はすでに4つの選択肢で、フローティングボタンの左に収まる幅がいっぱいである。
- 捨てた案：「他の言語」の言語ごとに専用の認識器を動かす。今の認識器で読める言語は、どれも既存の組（ラテン文字・中国語）で読めるので、専用の認識器は要らない。読めない文字（キリル文字・タイ文字など）の認識器を足すときに改めて決める。
- 再発を防ぐもの：機能の中では原文の言語を `Language` で持ち、文字認識に渡すときだけ `OcrLanguage` に変える（`docs/設計/画面翻訳.md`「原文の言語の指定」、`Language.kt` と `overlay/SourceLanguages.kt` の冒頭のコメント）。表と保存値の読み替えの試験は `SourceLanguagesTest`、メニューの行とサブメニューの言語の対応は `ScreenLanguageTest`。
