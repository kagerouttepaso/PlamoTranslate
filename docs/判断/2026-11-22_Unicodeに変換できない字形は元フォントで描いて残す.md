# Unicodeに変換できない字形は元フォントで描いて残す

- 状態：有効
- 問題：PDFium が Unicode に変換できない文字を置換文字にしていた。フォント名が空だと等幅の判定にも掛からず、元の字形を参照できないまま置換文字が翻訳に渡った。訳の記号は翻訳モデルが出した文字で、フォントの部分化による表示の欠けではなかった。
- 決めたこと：Unicode 対応がない文字は PDF の字形として保持し、翻訳モデルには置き場所を示すマーカーを渡す。確定訳で位置が決まれば、元フォントと文字コードで描いた字形を透過画像で置く。位置が決まらなければ段落を変えない。
- 理由：PDF 内の文字コードと Unicode が一致する保証はない。一方、元フォントと文字コードを指定すれば PDFium で元の字形を描ける。PDFium のページ書き出しは Type 3 の文字オブジェクトに対応していないので、画像として置くと保存後も字形を保てる。
- 捨てた案：PDFium が返す変換前の値をブラウザー版と同じように Unicode として使う案は、独自の文字コードを持つ PDF では別の文字になるため採らない。元フォントの文字オブジェクトを新しい位置に置く案は、保存で Type 3 の字形が失われるため採らない。
- 再発を防ぐもの：`docs/設計/PDF翻訳.md`「段落の組み立て」「訳文の配置」と、合成した Type 3 フォントで配置・保存・マーカーの欠落や重複を確かめる `PdfDocumentTest`。
