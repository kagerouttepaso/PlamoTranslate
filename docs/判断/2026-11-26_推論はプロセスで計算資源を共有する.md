# 推論はプロセスで計算資源を共有する

- 状態：有効
- 問題：Xiaomi 15T Pro では、画面に出ているアプリの作業スレッドに許された CPU は 4〜7 の4個だった。使用可能なプロセッサ数の API は8を返した。
- 決めたこと：推論のたびに作業スレッドで予算を読み、CPU の貸出合計を予算内に収める。GPU は1件ずつ貸す。中核が貸出の契約を定め、Android 版と Windows 版が組み立て時に同じプロセスの実装を渡す。翻訳と書き起こしは、許された CPU の性能の段からスレッド数の候補を作って試走する。
- 理由：見本音声の書き起こしは4スレッドで約0.6秒、5〜8スレッドで36〜39秒だった。会話中に翻訳4本と書き起こし4本が重なると、翻訳は136から2.2〜8.0トークン/秒に低下し、書き起こしは1文49秒かかった。各部品の上限だけでは同時使用時の競合を防げない。
- 再発を防ぐもの：`ComputeSchedulerTest` で予算の減少・待ち順・取り消し・性能の段を確かめる。`QwenAudioSessionTest` は予算の回復、解放と読み込みの順序、失敗後の再試行を確かめる。旧モデルを先に解放するのは、約1 GB のモデルを同時に2つ保持しないためである。実機では貸出のログと試走時間を照合する。
