# 設計書はコードを正本にして照らし識別子の消えを検査で止める

- 状態：有効
- 問題：0.11.0の会話翻訳・音声認識の作り直しで、コードは変わったが設計書が追いつかず、スレッドの組・ログの書式・区間の秒数・クラス名などが今の作りと食い違っていた。ほかの設計書・手順・資料にも、取得元や設定の項目の食い違いが溜まっていた。構造は、実装を変えたときに設計書を同じ変更で直す規則（`CLAUDE.md`「文書は役割を守って更新する」）はあるが、守られたかを確かめる仕組みが無く、別の作業の冷読で偶然見つかるまで残ったこと
- 決めたこと：
  - `docs/` の今の姿を書く文書をすべて今のコードと照らし、文書をコードに合わせた（計測の値と判断の記録は変えない）
  - `tools/check-docs.ps1` が、部品を説明する文書（`docs/設計/`・現在地・バックログ・要件・`CLAUDE.md`）が `…` で示す CamelCase・camelCase の識別子を、コードとファイルの名前の中から探し、無ければ誤りにする。Android・Gradle の外の名前は、スクリプトの短い一覧で許す
- 理由：名前が消えた・変わったのに文書が残る食い違いは機械で見つけられ、pre-commit と Stop フックで、変えた本人がその変更の中で直せる。振る舞いの食い違い（値・順番・条件）は機械で見つけにくいので、変更の進め方（`change-flow`）と文書の冷読（`docs-reader`）に任せる
- 捨てた案：資料と手順も検査の対象にする（Android の内部の名前や Gradle のタスク名が多く、許す一覧が膨らむ）
- 再発を防ぐもの：`tools/check-docs.ps1` の識別子の検査、`CLAUDE.md`「規則を支える仕組み」の表
