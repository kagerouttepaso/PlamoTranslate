# 同時に訳す数を3回の計測で自動調整する

- 状態：有効
- 問題：速い同時の数は端末によって違う。作者の要望「順に全部試すのではなく、少ない手数で最適な設定に入る形に」。
- 決めたこと：候補1・2・4・8本のうち、4本→1本→（4本が1本の1.1倍以上なら8本、そうでなければ2本）の3回だけ測る（`ParallelTuner`）。一番速い数より少ない数で9割以上出ていれば少ない方を選ぶ。
- 理由：REDMAGIC、2B・GPUのアプリでは1本25・4本36・8本39トークン/秒（生成だけ）で、プロンプトの処理を含めると4本が8本の9割以上なので4本を選んだ。CLIより伸びが小さいのは、早く終わる文があって同時に進む数が途中で減るためとみている。
- 捨てた案：候補を順に全部測る。
- 再発を防ぐもの：なし（選択）
