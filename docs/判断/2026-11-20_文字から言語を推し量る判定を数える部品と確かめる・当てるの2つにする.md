# 文字から言語を推し量る判定を数える部品と確かめる・当てるの2つにする

- 状態：有効
- 問題：書き起こした文の文字から言語を推し量る判定が4か所（話し手の根拠の日韓英中と、それ以外の言語、言語を指定せずに書き起こしたときの推定、訳す向き）にあり、文字の数え方も規則も少しずつ違った（半分以上か一番多いか、ラテン文字を a〜z だけ数えるか、ハングル優先か）。訳す向きの判定は日本語・韓国語・英語しか返さず、決まらなければ日本語にしていた。同じ問いを場所ごとに書いたので、場所が増えるほど規則が分かれていく構造だった。
- 決めたこと：用途を一段抽象化して2つに分ける。「確かめる」（判定された言語が文字と合うか。`LanguageEvidence`）と「当てる」（判定の無い文が候補のどれか。`ScriptLanguage.pick`）。どちらも共通の部品 `ScriptCounts`（文字の種類ごとの数と、言語ごとの合い方 0〜1）の上に置く。部品は言語ごとの合い方を返し、しきい値（半分以上）・同点の扱い・量が足りるかは2つの判定の中だけに置く。当てるのは、合う候補が1つならそれ、いくつも合えば合い方の一番高いもの、同点なら決めない。訳す向きでは簡体字と繁体字を1つの言語として当て、当てられなければ、文字があって自分の言語の文字でない文は相手、それ以外は自分とする（話した人を決めるのは訳す向きの決まりで、部品と判定は値を比べない）。中国語の判定は、中国語の相手なら中国語の文字で書かれているときだけ中国語とし、中国語の相手でなく会話に日本語があれば日本語の聞き違いとして扱う。文字はコードポイントで数え、絵文字と中黒は数えない。
- 理由：用途が同じものは1つの関数に、用途が違うものは共通の部品を使う別の関数にする（作者の決定）。答えの形が違う（はい・いいえ、と、どの言語か）ので2つの関数に分けた。合い方を言語ごとの値で返すのは、同じ文字を使う言語どうしの同点を消さずに表せ、声の識別のスコア（`SpeakerJudge` が受け取る言語ごとのスコア）と同じ形になるため（作者の決定）。日本語の合い方は日本語でも使う漢字だけを数えるので、簡体字の文は候補に中国語があれば中国語、無ければ日本語に合う。
- 変わった振る舞い（変更の前後で、端の例を含む33の文を、3つの判定と会話の設定の組で比べた。1,914件中74件が変わり、判定付きの日韓英の文の話し手の根拠と訳す向きは変わらなかった）：全角の英字を英字として数える。ラテン文字の言語の語はラテン文字の語だけを数える。日本語と判定された、日本語で使わない漢字の多い文は根拠にしない。判定なしの文は会話の言語から当てる（以前はハングルが少しでもあれば韓国語）。相手を固定した会話で、判定なしの、自分の言語の文字でない文は相手の発話にする（以前は日本語）。
- 捨てた案：当てる判定自体が言語ごとのスコアを返す。使う側がしきい値と同点の扱いを持つことになり、規則がまた呼ぶ側に散る。日本語で使わない漢字が1字でもあれば日本語に合わないとする（以前の推定の規則）。日本語と中国語を比べるときの規則で、中国語の候補が無い会話では日本語の聞き違いを相手の発話にしてしまう。
- 残したこと：相手不明で、判定の無いラテン文字の文が候補のいくつかに同じだけ合うと、自分の発話になる。「相手の発話で言語は未定」を表すには会話の中核の契約を変える必要があるので、バックログに置いた。
- 再発を防ぐもの：`docs/設計/会話翻訳.md`「文字の種類で言語を当てる・確かめる」。試験は `ScriptTest`（合い方と当て方）、`LanguageEvidenceTest`、`LanguageRouterTest`。
