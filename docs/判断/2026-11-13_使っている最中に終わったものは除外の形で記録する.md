# 使っている最中に終わったものは除外の形で記録する

- 状態：有効
- 問題：作者が画面翻訳中にアプリが落ちたのを試したが、不具合の記録に残らなかった。OS の記録では、画面翻訳のフォアグラウンドサービス中に「自分で終了コード0で終わった」（`REASON_EXIT_SELF`、状態0）になっていた。記録するかの判定（`ExitJudge.recordable`）は、使っている最中の終わり方を、メモリ不足・資源の使いすぎ・シグナルの3つだけ記録する許可の一覧にしていて、この終わり方が漏れた。一覧は featurelab で試した終わり方から作り、実際に起きる終わり方を想定していなかった（後で、REDMAGIC が窓の多いアプリを `System.exit(0)` で終わらせていたと分かった）。
- 決めたこと：異常終了はいつでも記録し、使っている最中に終わったものは、落ちたのではないと分かっている原因（本人の強制停止と、`ExitCause.OTHER` にまとめた更新・権限の変更など）を除いて全部記録する（除外の一覧 `BENIGN_WHILE_IN_USE`）。更新・権限の変更は専用の原因 `ExitCause.SYSTEM_CHANGE` に読み替え、知らない理由（`ExitCause.OTHER`）は記録する（受け皿を除外すると、同じ漏れが残る。リリースの前の設計レビューの指摘）。
- 理由：不具合の記録は調べるためのもので、知らない終わり方を記録しない誤りのほうが、余分に記録する誤りより重い。端末は OS の決まりの外でアプリを終わらせることがあり（`docs/資料/端末の能力.md`）、落ち方を数え上げきれない。アプリが自分で終えるときは印で除けるので、使っている最中の自分での終了は、意図しないものと見てよい。
- 捨てた案：許可の一覧に「終了コード0の自分での終了」を足す（同じ形の漏れを次も起こす）。
- 再発を防ぐもの：`ExitJudgeTest`（使っている最中に自分で終わったものを記録し、裏や更新は記録しない）。
