# 落ちたときの記録を端末に残して書き出せるようにする

- 状態：有効
- 問題：翻訳中や画面翻訳中にアプリが落ちることがあるが、手元で再現できないと、どこで落ちたかを知る手がかりが残らなかった。作者から「その辺のログを保存しておいて出力する機能がほしい」と要望を受けた。0.8.1 の端末に残っていた OS の記録には、画面翻訳のフォアグラウンドサービス中（重要度125、メモリ2.0GB）に SIGKILL で止められた終わり方があった。
- 決めたこと：落ちたときの記録を端末の中（`files/diagnostics/`）に残し、設定の「詳細」→「不具合の記録」から本人が zip に書き出す。例外は落ちる直前に受け口で書き、ネイティブの落ち方・応答なし・使っている最中に OS に止められたものは、次の起動で OS が残す終わり方（`ApplicationExitInfo`）から取り込み、その時点の端末のログを添える。同じプロセスの記録は、起動のたびに OS に預ける印（`setProcessStateSummary`）で見分けて1件にまとめる。アプリが設定を変えて起動し直すときは、印を「意図して終えた」に預け直し、記録しない。何を記録するか・どこにまとめるかの判定と保存の規則は中核（`pipeline.diagnostics`）に置き、GPU を外す判断と異常終了・意図した終わりの判定を共通にした。ファイルの保存の実装は `app` に置く。
- 理由：ネイティブのライブラリ（llama.cpp・ONNX Runtime・sherpa-onnx）で落ちたときと OS に止められたときは、プロセスの中では受け止められず、`ApplicationExitInfo` でしか知れない（Android 11以降。このアプリは Android 13以上）。例外の受け口だけでは、作者が困っている落ち方の多くを拾えない。逆に OS の記録だけでは、Kotlin の例外のスタックトレースが残らない（OS の説明は「crash」の1語）。ログは落ちた直後に写すのが一番よいが、プロセスはもう無いので、次の起動の早いうち（`Application.onCreate` の裏のスレッド）に写す。送り先を作らず、書き出しを本人の操作に限るのは、ログに会話の文や訳が入るため。featurelab で確かめると、自分で `killProcess` した終わり方は OS の記録では SIGKILL と見分けがつかず、例外で1回落ちると OS の記録が2件残った。時刻の近さでまとめる案は、2件目が「停止しました」を閉じるまで遅れるので、決まった幅を置けない。印はどの終わり方でも OS の記録に戻った。
- 捨てた案：pid と時刻の近さ（60秒）でまとめる（幅に仕組みの裏付けが無く、遅れた2件目や pid の再利用で外れる）。外部のクラッシュ収集サービス（Firebase Crashlytics など。端末の外へ送ることになり、「訳す内容を送らない」方針に反する）。常にログをファイルへ書き続ける（端末の容量と電池を使い、ふだんは要らない）。使っている最中でない OS の終了も記録する（裏に回った後の片付けはふつうの生き死にで、記録が埋まる）。
- 再発を防ぐもの：`ExitJudgeTest`（記録するか、意図した終わり、同じプロセスの2件をまとめる）、`CrashJournalsTest`（足す先、ファイルの名前、件数の上限、zip の中身）、`FileCrashJournalTest`（保存の実装）、`GpuGuardTest`（起動し直しで GPU を外さない）。`docs/資料/端末の能力.md`「プロセスの終わり方」。`docs/設計/アーキテクチャ.md`「不具合の記録」。
