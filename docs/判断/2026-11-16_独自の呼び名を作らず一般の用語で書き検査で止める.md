# 独自の呼び名を作らず一般の用語で書き検査で止める

- 状態：有効
- 問題：文書・コメント・画面で、作業中に付けた和語の呼び名（キャッシュ・バッジ・ウィンドウ・イベントなどを言い換えた語）を使っていて、作者に伝わらなかった。構造は、一般の用語がある概念に名前を作ってよいかの決まりが無く、一度入った呼び名が「用語」の表と設計書を通して文書・コード・画面へ広がったこと。同じ語彙を持つブラウザー拡張版でも同じことが起き、そちらで先に整理した
- 決めたこと：
  - 独自の呼び名を作らない。開発文書・コメント・試験名・ログは一般の技術用語と識別子・Android の正式な名称で、画面・README・プライバシーポリシー・ストア掲載文は技術者でない利用者に通じる一般的な名称で書く
  - 以前使っていた呼び名と、代わりに使う語・検査の形の表を `docs/設計/アーキテクチャ.md`「使わない言い換え」の1か所に置く
  - `tools/check-docs.ps1` がその表を読み、表の語が文書・コード・画面・ファイル名に戻ったら誤りにする。表を正本にし、語をスクリプトに書き写さない
  - 置き換えに合わせて、題に呼び名を含む判断の記録のファイル名も変えた
- 理由：作者の指摘。一般の用語なら、文脈を知らない読者（作者・別のPCのAI）にもそのまま通じる。和語で書く方針（`docs/README.md`）は文の書き方に効かせ、概念の名前には使わない
- 捨てた案：語ごとに文書の注釈で意味を説明する（読者が注釈を探す負担が残り、新しい呼び名も止まらない）。表を検査のスクリプトに持つ（表と検査の二重管理になる）
- 再発を防ぐもの：`CLAUDE.md`「独自の呼び名を作らない」、`docs/設計/アーキテクチャ.md`「書き方の決まり」「使わない言い換え」、`tools/check-docs.ps1`（pre-commit と Stop フックで回る）、文書の冷読（`.claude/agents/docs-reader.md`）で表に無い呼び名を拾う
