# 音声認識モデルを設定で選び言語の識別を独立した段にする

- 状態：有効
- 問題：会話翻訳で聞ける言語が SenseVoice の5言語に限られ、ロシア語・ヒンディー語などを話す相手と話せなかった。言語の識別が認識器のおまけになっていて、話し手の交代（`LanguageEvidence`）も訳す方向（`LanguageRouter`）も、SenseVoice が書き起こしと一緒に返す言語タグに頼っていた。言語を返さない認識器（Qwen3-ASR など）に替えると両方が働かない。会話の言語の一覧も SenseVoice に決め打ちで、画面が `SenseVoiceAsr` を直接読み込んでいて、モデルを選ぶ入口が無かった。
- 決めたこと：
  - 音声認識モデルは、翻訳モデルと同じく設定の画面で前もって選ぶ（`SpeechModel`）。会話の言語で認識器を自動で切り替えない。テキスト翻訳の音声入力も同じ設定に従う。
  - 会話で選べる言語は、選んだモデルが聞け、かつ PLaMo が訳せる言語にする。
  - 音声認識を区切り・言語の識別・文字起こしの段に分け、言語の識別は認識モデルから独立させる。既定の識別は Whisper tiny。モデル自身の判定の方が確かなモデル（SenseVoice）は、その判定を使う。どちらを使うかは `SpeechModel` で宣言し、`SpeechEngines.load` が組み立てる。
  - 識別は会話の言語に絞り、決めた言語を指定して書き起こす。
  - Qwen3-ASR 0.6B を選べるようにし、Whisper tiny の識別モデルと1つの組で、設定の画面でそのモデルを選んだときに取る（読み上げの Supertonic 3 と同じ）。
- 理由：REDMAGIC 11 Pro のデバッグ版の `AsrBenchActivity` で、5秒前後の発話の Whisper tiny の識別は0.23〜0.3秒（sherpa-onnx の識別で測った値。今の ONNX Runtime で直接動かす識別は測っていない）、Qwen3-ASR の書き起こしは4スレッドで1.3〜2.0秒、6スレッドで0.6〜1.5秒（SenseVoice は約0.15秒）。識別は日・露・仏・独・西・英で正しく、アラビア語をトルコ語と誤った。仏語は言語を指定しないと書き起こしが崩れ、指定すると正しくなった。違う言語を指定しても崩れる（アラビア語がローマ字になった）ので、識別は会話の言語に絞ってから渡す。Qwen3-ASR の読み込みでメモリが約1.1GB増える。sherpa-onnx 2.0.1 は Qwen3-ASR 自身の言語の判定を返さない（PCで確かめた）ので、Qwen3-ASR には外の識別が要る。音声認識モデルを前もって選ぶ形にし、会話の言語で認識器を自動で切り替えないのは作者の決定。
- 捨てた案：会話の言語に合わせて認識器を自動で切り替える案（2つの認識モデルを持つとメモリが増える）。日・韓・英・中の発話だけを SenseVoice へ振り分ける案は決まっていない（`docs/バックログ.md`「決まっていないこと」）。
- 再発を防ぐもの：中核のインターフェース（`SpeechRecognizer`・`LanguageIdentifier`）と、モデルごとの性質を1か所で宣言する `SpeechModel`。設計は `docs/設計/会話翻訳.md`「エンジンと出来事」。
