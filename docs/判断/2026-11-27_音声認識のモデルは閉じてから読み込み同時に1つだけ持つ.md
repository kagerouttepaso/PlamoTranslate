# 音声認識のモデルは閉じてから読み込み同時に1つだけ持つ

- 状態：有効
- 問題：REDMAGIC 11 Pro で翻訳を CPU で動かすと、会話翻訳を開いたときの書き起こしの試走で、前面のままプロセスが OS に止められた（シグナル9）。試走は Qwen3-ASR の候補を比べる間、それまでの最速の認識器を開いたまま次の候補を読み込んでいた。認識器1つで匿名メモリが約1.5 GB 増え、翻訳の CPU のモデルと合わせて RSS が約5.9 GB になり、端末の `lowmemorykiller` が止めた。試走の結果は終わるまで保存しないので、開くたびに同じ所で止められた。構造は「重いモデルの入れ替えで、新しい方を作ってから古い方を閉じる（古い方の解放を待たない）」で、ONNX の音声部品のスレッド数の変更と、画面を閉じた直後に開き直す経路にも同じ形があった。
- 決めたこと：音声認識のモデルは、古い方を閉じて解放が終わってから新しい方を読み込み、同時に1つだけ持つ。Qwen3-ASR は、プロセスで1つの許可（`QwenAudioRecognizer` の `modelSlot`）を試走の始めから採用した認識器の解放まで持ち、次の読み込みは許可が返るまで待つ。試走は候補を読み込む前に持っている認識器を閉じ、採用した候補が手元に無ければ読み込み直す。ONNX の音声部品（SenseVoice・Whisper tiny）も、スレッド数を変えるときは閉じてから作る。認識器を長く持つ画面は、画面を離れて聞いていなければ解放する。
- 理由：同じ端末と設定で、直す前は8本の候補を読み込んでいる間に止められた。直した後は試走が最後まで通り、RSS の最大は4.1 GB だった。読み込み直しは試走をやり直す初回だけ1回増える（直した後に REDMAGIC 11 Pro で測った準備の時間は、翻訳が CPU で33秒、翻訳が GPU で65秒。読み込み直しは約4秒）。
- 捨てた案：空きメモリを見て、余裕があるときだけ2つ持つ（端末ごとの止める基準が分からず、確かめた範囲を外れる）。
- 再発を防ぐもの：`TranscriptionTunerTest` と `ScheduledSpeechTest` の偽の読み込みが、読み込む時点で開いているモデルが無いことを確かめる。`QwenAudioRecognizerTest` が、解放が終わるまで次の読み込みを待つことを確かめる。規則は `docs/設計/アーキテクチャ.md`「計算資源の割り当て」。`docs/資料/端末の能力.md`（REDMAGIC が前面のアプリをメモリで止めること）。
