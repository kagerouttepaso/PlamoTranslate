# ライセンスの表示を同梱した全文と明記にする

- 状態：有効
- 問題：「このアプリについて」は、モデルとライブラリの名前・ライセンス名・リンクを並べるだけで、ライセンス名を「リンク先のライセンス」とぼかした項目もあった。APK に組み込んで配るライブラリ（MIT・BSD・Apache-2.0）は、配布物にライセンス文と著作権表示を含めることを求めるので、リンクだけでは足りなかった。ML Kit が利用の指標を Google へ送ることを、ML Kit の規約は利用者に知らせるよう求めるが、画面は「通信するのはダウンロードと更新の確認だけ」と事実と違うことを書いていた。読み上げの Supertonic 3（BigScience Open RAIL-M）は使う人に用途の制限を守らせるよう求めるが、表示も同意も無かった。0.8.0で足した韓国語の文字認識のモデルは、一覧に載っていなかった。
- 決めたこと：作者の決定で、次のようにする。
  - アプリに含まれるソフトウェアのライセンス文の全文を `assets/licenses/` に同梱し、「このアプリについて」から読めるようにする。依存を足す生成の仕組み（oss-licenses-plugin など）は使わず、手で書く分と `tools/collect-licenses.py` が作る分に分ける。
  - モデルは名前・作者・ライセンス名・配布元を明記し、ぼかした書き方をやめる。
  - ML Kit の指標の送信を画面とプライバシーポリシー（`PRIVACY.md`）に書き、要件の「通信しない」をこれに合わせて直す。
  - Supertonic 3 のダウンロードの前に、用途の制限の要旨と全文を見せて同意を取る。
  - 非公式であることを明記する。PFN が法人向けに同じ名前の製品を出しているので、アプリの表示名は変える（名前は作者が決める）。
- 理由：外の一次情報（各リポジトリの LICENSE、モデルカード、ML Kit の規約、OpenRAIL-M の条文）と、0.8.0 の APK の中身を照らした。GPL のコードは入っていない（sherpa-onnx は 2.0.0 で espeak-ng を取り除き、`libsherpa-onnx-jni.so` に espeak-ng の本体が無いことを確かめた）ので、ソースを公開する義務は無い。モデルはアプリに含めず端末が配布元から取るので、再配布の義務は配布元にあるが、OpenRAIL-M 第5項と ML Kit の規約はアプリの作者に直接かかる。
- 捨てた案：Google の oss-licenses-plugin（依存と画面が増え、CMake で作るものとローカルの AAR は結局手で書く）。名前とリンクだけを直す（全文を含める条件を満たさない）。
- 再発を防ぐもの：依存やモデルを変えたらライセンス文を集め直す手順（`docs/手順/開発環境.md`「ライセンス文を集め直す」、リリースの手順の2）。`tools/collect-licenses.py` は、ライセンスの分からない依存が増えると止まる。
