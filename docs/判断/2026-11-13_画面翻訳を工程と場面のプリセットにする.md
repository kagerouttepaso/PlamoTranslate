# 画面翻訳を工程と場面のプリセットにする

- 状態：有効
- 問題：ゲームのUI・チャット・漫画で合う行のまとめ方が違うのに、画面翻訳は吹き出し向けのまとめ方（`LineClusterer`）しか選べなかった。カメラ翻訳の文章・表のまとめ方は別の場所に別の型で書かれ、使い回せなかった。吹き出しに広げる枠は背景色が閉じているかだけを見ていて、メニューの並びで広げると隣の項目に重なりえた（「ほかの文字にかかるなら広げない」で抑えていた）。
- 決めたこと：作者と合意した方針で、画面翻訳を工程（撮る → 読む → まとめる → 選ぶ → 枠を決める → 訳す → 流し込む）の並びとして固定し、差し替えるのはまとめ方と枠の決め方だけにする。まとめ方3つ（吹き出し・文章・メニュー）と占めてよい範囲は中核（`pipeline.layout`）に置き、カメラ翻訳も同じ部品を使う。訳の単位に種類と占めてよい範囲を持たせ、枠はそれだけを見て広げ、余白を足した後も範囲で切る。場面のプリセット（漫画・チャット・ゲーム）は工程の中身の組に名前を付けたデータにし、メニューで選ぶ。1回の翻訳のデータは、変わらない前提（`ScreenFrame`）と、工程ごとに1度だけ置く結果に分ける。
- 理由：まとめ方と枠の広げ方を独立に選べるようにしても、範囲で切れば組み合わせを禁止する規則が要らない。まとめ方は判断なので、Android に依存しない中核に置くと単体テストで約束（どの行も1つの単位に入る、範囲は原文を含み重ならない）を確かめられる。プリセットに処理の分岐を書かないので、アプリごとに場面を自動で切り替える部品も同じ組を当てるだけで足せる。
- 振る舞いの変化：今までの設定（吹き出し）でのまとまりは変えていない（規則を試験で固定して移した）。広げた枠は、ほかの文字にかかるときに広げないのでなく、範囲で切って広げる。余白を足した枠も範囲で切る。状態バーの高さと工程の中身は、文字を読んだ後でなく撮れた直後に決める（メニューを開くと取り消すので、セッションの途中で変わらない）。
- 確かめていないこと：文章・メニューのまとめ方とプリセットの質は、評価の画像が無く端末もつなげなかったので、評価（`tools/run-bench.ps1`）でも実機でも見ていない。
- 捨てた案：認識器やまとめ方を登録するプラグインのような汎用の仕組み（先回りして作らない）。撮り方・判定器もインターフェースにする（実装が1つで、値の違いで足りる）。組み合わせごとに禁止の規則を持つ（範囲で切れば要らない）。
- 再発を防ぐもの：`docs/設計/画面翻訳.md`「工程とデータ」「まとめる」「占めてよい範囲」「場面」、`GroupersTest`・`RoomsTest`・`ScreenPresetTest`。
