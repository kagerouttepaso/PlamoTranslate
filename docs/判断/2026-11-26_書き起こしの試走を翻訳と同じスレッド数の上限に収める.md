# 書き起こしの試走を翻訳と同じスレッド数の上限に収める

- 状態：置き換え（→ [推論はプロセスで計算資源を共有する](2026-11-26_推論はプロセスで計算資源を共有する.md)）
- 問題：Xiaomi 15T Pro（MT6991、Android 16）で Qwen3-ASR を選ぶと、初回の準備に数分かかった。v0.14.0 は8コアを候補の上限にしていたが、推論スレッドが使えたのは CPU 4〜7 の4コアだった。エンコーダー／一括評価／生成が 4/4/4 のときは既知音声1回に約0.6秒、6/6/6 では約30秒かかり、各候補を4回ずつ試していた。
- 決めたこと：書き起こしでも翻訳の既定スレッド数を各段の上限とする。使用可能な CPU 数にも収め、重複する候補は一度だけ試す。CPU と GPU の比較では、ならしに暫定首位の中央値の4倍を超える時間がかかった候補を閉じ、次の計測に進む。
- 理由：翻訳でも同じ端末の6スレッドは0.3〜0.8トークン/秒、4スレッドは56〜62トークン/秒だった。翻訳と上限を共有すると、15T Pro では 4/4/4 だけを試し、上限が6の REDMAGIC 11 Pro では 4/4/4、6/6/6、6/6/4 を比較できる。打ち切りには端末ごとの処理時間を使い、初回だけの遅延を許すため4倍の余裕を取る。採用する候補は従来どおり3回とも本文と言語が一致したものに限る。
- 再発を防ぐもの：`ThreadCountTest` で端末構成ごとの上限を、`TranscriptionTunerTest` で候補の重複排除、打ち切り、認識器の解放と選択の保存を確かめる。
