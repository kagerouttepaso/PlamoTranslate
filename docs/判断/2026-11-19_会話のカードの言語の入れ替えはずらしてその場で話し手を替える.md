# 会話のカードの言語の入れ替えはずらしてその場で話し手を替える

- 状態：有効
- 問題：自動の判定が外れて言語を取り違えた確定したカードを、利用者が直す手段が無かった。確定したカードの音声は確定した時点で捨てていたので、別の言語で書き起こし直せなかった。また SenseVoice は言語を指定した書き起こしができず（書き起こしの言語の指定を無視する）、両方の認識モデルで同じように直す口も無かった。
- 決めたこと：
  - 確定した発話の音声を直近10枚だけメモリに保持し（`UtteranceRetention`）、音声認識の命令 `retranscribe` で、保持した音声を指定の言語で書き起こし直す。SenseVoice でも Qwen3-ASR でも同じ命令で動く。SenseVoice は、言語を固定した認識器を必要なときに読み込む。
  - 操作は、確定したカードをもう一方の話し手のカードが寄る位置へ横にずらす形にする。カードはその位置までしか動かず、届いたら振動する。動かすにつれて色がもう一方の話し手の色へ移る。
  - 離したら、会話の中核はその場で向き（話し手）を替え、原文は書き起こし直しが届いてから差し替えて訳す。書き起こし直せなければ元のカードに戻す。
  - 入れ替えられることは、入れ替えられるカードには何も足さず、もう入れ替えられない古いカードの側で示す。古いカードは色を背景色へ少し寄せ、ずらしても少し動いて跳ね返る。
- 理由：
  - 保持を直近10枚にしたのは作者の決定：取り違えに気づいて直すのは直近の数枚である。メモリは最大約9MBに収まる。
  - 操作の形と見せ方は作者の決定：入れ替えた手応えがあり、待ち時間の間も入れ替えたことが見え、画面が不連続にならないこと。
- 捨てた案：
  - **カードを画面の端までずらせる形、離すと元の位置へ戻り、書き起こし直しが届くまで見出しの「⇄ …」だけを変える形**（最初の作り）：入れ替えた手応えが無く、待ち時間の間に何が起きているか分からず、届いた時に別の色のカードへ跳んで不連続だった。
  - **入れ替えられるカードの角に記号（⇄）を出す**：1画面のカードの見出しと重なり、対面のカードには置く余地が無かった。
  - **入れ替えられるカードの縁にハンドル（縦の短いバー）を出す**：細く薄くしても主張が強かった。
  - **SenseVoice の言語を `OfflineRecognizer.setConfig` で切り替えて書き起こし直す**：sherpa-onnx 2.0.1 のソースで、SenseVoice の読み込み時に直す特徴量の設定（ウィンドウ関数の種類・正規化）が、`setConfig` で初期値に戻る。書き起こしごとの `setOption("language")` は SenseVoice に効かない（PC で確かめた）。
- 再発を防ぐもの：
  - 規則：自動の判定で取り切れないものは、利用者が直す手段を置き、利用者の指定をどの判定よりも先にする（`docs/設計/アーキテクチャ.md`「設計の原則」の8）。
  - 設計：`docs/設計/会話翻訳.md`「画面」の「言語の入れ替え」と「カードの言語の取り違えを直す」。
  - 試験：`UtteranceRetentionTest`、`RecognitionQueueTest`（書き起こし直しを捨てない）、`ConversationSessionTest`（入れ替え・失敗・入れ替えられないカード）、`LanguageRouterTest`（認識器に指定する言語）。
