# 文末の無音では途中の書き起こしを頼まない

- 状態：有効
- 問題：書き起こしのワーカーは1本で、優先順位が効くのは次のジョブを取るときである。文末の後にも、定期更新や遅れて届いた言語判定をきっかけに途中の書き起こしを頼んでいた。これが先に走ると、確定に使う文が待つ。以前の Windows での測定では、Qwen3-ASR が実行中の途中認識を4.38秒待ち、文の処理に2.31秒、発声終了から確定訳まで8.25秒かかった回がある。
- 決めたこと：中核の `SpeechSegmenter.requestPartial` は、VAD が文末を検出してから次の発話を検出するまで（`inGap`）、新しい途中の書き起こしを頼まない。文の言語判定・書き起こしとカードの確定はそのまま進める。
- 理由：`inGap` は、終わった文を確定用の処理に渡し、次の文の音声がまだ来ていない区間を表す。既存の文末判定（既定で無音0.6秒）を使えば、音量や機種ごとのしきい値を増やさず、Android と Windows で同じ判断ができる。文末を検出する前に依頼したジョブは実行されるため、そのジョブが原因の待ちは残る。
- 捨てた案：書き起こしワーカーの増設と実行中の認識の中断は採らない。無音だけが増えた音声に対する新規の依頼は、並列実行や中断の仕組みを増やさずに防げる。
- 再発を防ぐもの：`SpeechSegmenterTest` で、文末の後に更新間隔が過ぎた場合と言語判定が届いた場合の両方を確かめる。発話を再開すると同じカードで途中認識が戻り、前後の文が確定原文に残ることも確かめる。規則は `docs/設計/会話翻訳.md`「認識の段と CPU の割り当て」。

## Windows での時間

マイク相当の入力として16 kHz の PCM を10 msずつ実時間で供給し、PC 版の `AudioPresenter`、`DesktopAsr`、翻訳ストリームを通した。Windows 11、Core i3-12100（4コア8スレッド）、RTX 4060。書き起こし4スレッド、Whisper tiny の識別2スレッド、カードの言語判定に2秒、PLaMo 0.8B は Vulkan。各条件で同じ順に、英語の短い合成音声、FLEURS の日・英・韓各1文、冒頭と同じ合成音声を流した。1入力につき1枚、各モデルで前後5枚ずつ。自分は日本語、相手の言語を指定し、話し手は自動判定とした。

発声の端は、各音声の10 msごとの実効値がその音声の最大実効値の1割を超えた最初と最後のパケットとした。パケットに付けた実測時刻から音声上の時間差で換算した。原文・訳は会話カードの状態に文字が現れた時刻。途中認識の待ち時間は、確定に要るジョブが書き起こしの列で待った区間と、そのワーカーが途中認識を実行した区間の重なりをカードごとに合計した。同じ時間は1回だけ数え、待ちがなければ0秒とした。物理マイクと画面の再描画は計測に含まない。

各欄は5枚の中央値 / 最大値（秒）。途中原文と途中訳は、全条件で5枚とも表示された。

| 指標 | Qwen3-ASR 前 | Qwen3-ASR 後 | SenseVoice 前 | SenseVoice 後 |
| --- | ---: | ---: | ---: | ---: |
| 発声終了 → 確定原文 | 3.539 / 5.350 | 4.009 / 5.000 | 3.281 / 4.162 | 3.284 / 4.162 |
| 発声終了 → 確定訳 | 3.740 / 5.762 | 4.243 / 5.315 | 3.457 / 4.368 | 3.605 / 4.515 |
| 確定用ジョブが途中認識を待った時間 | 0.323 / 1.124 | 0.291 / 0.731 | 0.000 / 0.000 | 0.000 / 0.002 |
| 発声開始 → 最初の途中原文 | 3.875 / 4.658 | 3.780 / 4.692 | 2.637 / 3.014 | 2.794 / 3.016 |
| 発声開始 → 最初の途中訳 | 4.225 / 4.998 | 4.129 / 5.084 | 3.009 / 3.321 | 3.126 / 3.282 |

Qwen3-ASR の途中認識は5枚で 8 → 8件。前後とも4枚で確定用ジョブが途中認識を待った。待ちの最大値は下がったが、確定訳の中央値は延びた。この5枚から確定訳の高速化は確認できない。SenseVoice の途中認識は 55 → 30件に減った。確定用ジョブが途中認識を待った時間は変更前が全件0秒、変更後も最大2 msだった。

最初の途中訳について、変更後に最初の言語判定を頼んだのは、両モデルとも発声開始から中央値2.27秒だった。最初の途中認識を頼むまでの中央値は Qwen3-ASR が2.38秒、SenseVoice が2.53秒で、そのジョブが終わるまでがそれぞれ発声開始から3.62秒と2.79秒。短い英語の2回では Qwen3-ASR の途中認識が終わった後、文の認識結果が表示されるまで最初の途中原文が出なかった。発話冒頭の言語判定と、判定後の書き起こし・表示・翻訳が途中訳の時刻を決めている。
