# 認識を段に分け確定に要る処理を先にする

- 状態：有効
- 問題：書き起こしの速いモデル（SenseVoice）の前提で、止まってはいけない処理（録音・音量・区切り・話し手の判定）と重い書き起こしを、同じ1本のスレッドに順に並べていた。同じ音声を途中結果と文の終わりで2回書き起こし、途中結果のたびにカード全体と言語の監視を書き起こし直してもいた。翻訳（llama.cpp）は GPU で動いていても CPU のスレッドを持ち、音声認識と CPU を取り合う見込みもあった。そのため Qwen3-ASR（書き起こし1回に1〜2秒）を選ぶと、重い書き起こしの後ろに音声・区切り・話し手の判定が待たされ、音量のバーと話し中のカードの文字が止まり、「書き起こし中」が5〜7秒続いた。
- 決めたこと：
  - 音量は録音の側で測り、音声認識へは上限の無い列で渡す。認識が1秒以上遅れたら、その秒数を話し中のカードに出す。
  - 文ごとに1回だけ書き起こしてつなぐ。話し手の判定は書き起こさずに識別で行う。
  - セグメンター（`SpeechSegmenter`）を、音声と認識の結果を受け取ってジョブを出す状態遷移にし、書き起こしと識別をワーカーのスレッドに分ける（`SpeechPipeline`）。ジョブは確定に要るものを先にし、出来事はカードの順に出す。
  - 確定に要るジョブが残っている間は途中訳を始めない。スレッド数（書き起こし・識別・会話中の翻訳）は詳細設定の1か所で決め、変えて測れるようにする。
  - 話し中のカードには、文字より先に誰が何語で話しているかと「書き起こし中… N秒」を出す。区切るボタンは押したその場でカードを区切り、書き起こし待ちのカードとして並べる。
  - 話した言葉は落とさない。同じ音声を何度書き起こすかはモデルの性質で決めてよい。カードの言語を決める長さは設定で変えられる。
- 理由：5秒前後の発話で、Qwen3-ASR の書き起こしは0.6〜2.0秒（スレッド数で変わる）、識別は0.23〜0.3秒（sherpa-onnx の識別で測った値）かかり、合わせると、`docs/要件.md`「性能の目標」の途中訳の更新間隔（1秒以内）に届かない（[音声認識モデルを設定で選び言語の識別を独立した段にする](2026-11-17_音声認識モデルを設定で選び言語の識別を独立した段にする.md)）。重い処理は速くできないので、止まってはいけない処理（録音・音量・区切り・話し手の判定）を重い処理から切り離し、それぞれの今の状態をすぐ画面に出す。話した言葉を落とさないことと、同じ音声を何度書き起こすかをモデルの性質で決めることは作者の決定。スレッド数は、llama.cpp が2の累乗で速く3や6で遅くなった経験がある（作者）一方、Qwen3-ASR は4と6しか測っていないので、定数にせず設定で変えて測る。
- 捨てた案：日・韓・英・中の発話を SenseVoice へ振り分ける案は最終手段として残す（メモリが増え、音声認識モデルを前もって選ぶ形から外れる）。
- 再発を防ぐもの：規則「止まってはいけない処理（録音・判定・制御）と重い推論は別のスレッドに置き、重い推論の待ちで前者を止めない」を `docs/設計/アーキテクチャ.md`「計算資源の割り当て」に置いた。会話翻訳での分け方は `docs/設計/会話翻訳.md`「認識の段と CPU の割り当て」。`RecognitionQueue` の約束（`reset` と `close` の間に頼んだジョブには、処理しても捨てても失敗しても1回だけ結果を返す）と `SpeechPipelineTest`（認識が失敗しても止め終わりが届く）。
