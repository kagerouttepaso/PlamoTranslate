# 訳の控えを多層の控えとして定め鍵を契約に置く

- 状態：有効
- 問題：控えは翻訳の契約の添え物として層ごとに足され、鍵と約束がばらばらだった。1次（メモリ）は原文だけを鍵にし、範囲をそろえるのは呼ぶ側の注意だけだった。2次（データベース）の範囲は画面翻訳のサービスが `Options` と別に組み直し、背景と言い方（`form`）が入っていなかった。モデルの扱いも層で違い（1次はエンジンが変わると捨て、2次は確かさで選ぶ）、書く約束はどこにも書かれていなかった。そのため契約を作り替えたときに書く段が漏れた（[流れを閉じても訳し終えた片は控えに書く](2026-11-13_流れを閉じても訳し終えた片は控えに書く.md)）。
- 決めたこと：
  - 控えを契約の多層の控えとし、1次をメモリの控え `MemoryCache`、2次を永続の控え `PersistentCache`（実装は `SqlitePersistentCache`）と呼ぶ。
  - 鍵は両層とも「範囲 `CacheScope`（原文の言語・訳す先・言い方・背景）＋片の原文」にし、範囲は契約が `Options` から作る。原文の言語の自動と明示は別の範囲にする。
  - 両層とも、訳したモデル `ModelOrigin` の確かさ（`quality`）が今のモデル以上の訳だけを使い、モデルを切り替えても捨てない。確かさは、モデルの大きさでなく抽象の順位として持つ。
  - 2次を消した世代は契約が扱い、1次を捨て、書くときに訳し始める前の世代を渡す。
  - 約束は `docs/設計/翻訳コア.md`「控え」に一覧で置き、約束ごとに `TranslationStreamTest` の試験を置く。
- 理由：作者の決定（多層の控えとしてポリシーを定める、モデルの切り替えでは確かさで選ぶ、自動と明示を分ける、言い方を鍵に入れる）。1次を差し込み口にしないのは、ロックの中と推論スレッドから同期で引くためで、2次（suspend で IO へ移る）と同じ口に並べると「途中は1次だけ」の約束が型で表せなくなる。差し替える実装も無い。
- 捨てた案：1次も差し込み口にして層を同じ口で並べる（上の理由）。カメラ翻訳の訳の表を1次の差し替えにする（表示の状態で、時系列で原文を安定させる層の仕事なので、契約の控えへ寄せると情報が切れる。`docs/バックログ.md`「リファクタリング」の「カメラ翻訳の訳の対応表を見直す」）。
- 再発を防ぐもの：`docs/設計/翻訳コア.md`「控え」の約束の一覧と、約束ごとの `TranslationStreamTest` の試験（範囲、範囲の違う共有、確かさ、2次からの昇格、世代、閉じても・取り消しても書く）。
