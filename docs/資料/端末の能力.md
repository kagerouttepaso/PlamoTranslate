# 端末の能力

端末とOSで何が届き、何が撮れるかを、機能テスト用のアプリ（`featurelab`）で1つずつ確かめた事実をまとめる。設計書はここを前提にする。断りが無い限り、REDMAGIC 11 Pro（Android 16、ジェスチャー操作 `navigation_mode=2`）で2026-11-12に確かめた。このアプリを作った理由は `docs/判断/2026-11-12_端末の能力を機能テスト用のアプリで先に確かめる.md`。

## 機能テスト用のアプリ

`featurelab` は本体とは別のアプリ（パッケージ名 `app.plamotranslate.featurelab`）で、配布しない。ほかのモジュールに依存せず、窓単位の撮影（`takeScreenshotOfWindow`）を使うので minSdk は34である。

| 部品 | すること |
| --- | --- |
| `LabA11yService` | ユーザー補助。出来事を全種類（`typeAllMask`）とキー入力を受け、種類・アプリ・窓の番号・変化の種類・スクロール量だけをログに残す。窓の中身（文字やビュー）は読まない。撮影と窓の一覧の権限を持ち、PCからの命令を受ける |
| 重ね表示 | 紫の四角（ユーザー補助の重ね表示 `TYPE_ACCESSIBILITY_OVERLAY`）と水色の四角（ふつうの重ね表示 `TYPE_APPLICATION_OVERLAY`、不透明度0.8）。どちらも400×200。撮った画像でこの色の画素を数え、写ったかを見る（`Lab.describe`。全部写れば80000画素） |
| `SurfaceTestActivity` | 専用の描画面（`SurfaceView`）を緑で塗り、白い帯を動かす。ゲームや動画と同じ描き方が撮れるかを見る |
| `CaptureService` | 画面共有（`MediaProjection`）で撮る |
| `MainActivity` | 許可の設定を開くボタン、重ね表示・撮影・画面共有のボタン、ログの末尾 |

### 使い方

1. `.\gradlew.bat :featurelab:installDebug` で入れる。
2. 端末で「機能テスト」を開き、「重ね表示の許可を開く」で許可し、「ユーザー補助の設定を開く」で「機能テスト（合図の計測）」をオンにする。
3. `adb shell setprop log.tag.FeatureLab V` でログを開け（理由は「設計に効く、思わぬ事実」）、`adb logcat -s FeatureLab` で読む。
4. PCから命令を送る。引数のある命令は、端末のシェルで1つの値になるように引用符で囲む。

   ```text
   adb shell am broadcast -a app.plamotranslate.featurelab.CMD --es cmd windows
   adb shell "am broadcast -a app.plamotranslate.featurelab.CMD --es cmd 'burst 250'"
   ```

5. 描画面の試験は `adb shell am start -n app.plamotranslate.featurelab/.SurfaceTestActivity` で開く。
6. 調べ終わったら、ユーザー補助をオフにし、端末を片付ける（`docs/手順/開発環境.md`「端末の片付け」）。

| 命令 | すること |
| --- | --- |
| `overlay_on`・`overlay_off` | 紫（ユーザー補助の重ね表示）を出す・消す |
| `app_overlay_on`・`app_overlay_off` | 水色（ふつうの重ね表示）を出す・消す |
| `shot` | 画面全体を1回撮る（`takeScreenshot`） |
| `burst <ms>` | 画面全体を8回、前の撮影の終わりから `<ms>` あけて撮る |
| `window_shot` | 前面のアプリの窓を1回撮る（`takeScreenshotOfWindow`）。画像を `files/lab/` にPNGで保存する |
| `window_burst <ms>` | 前面のアプリの窓を8回撮る。1回目の画像を保存する |
| `windows` | 窓の一覧（番号・種類・層・題名・前面か・範囲）をログに出す |
| `auto_shot_on`・`auto_shot_off` | 1秒ごとに前面の窓を撮り、明るさ・真っ黒の割合・紫・水色・緑の画素数だけを残す（画像は保存しない） |
| `snap` | 画面共有で1枚撮る（先に画面の「画面共有を始める」で始めておく） |
| `mark <文>` | ログに区切りの行を入れる |

## 問い1：戻る・ホーム・画面の移動で、どの合図が届くか

戻る操作そのものは届かない。届くのは、その結果として「別の画面・別の窓になった」「中身がスクロールした」という出来事である。Discord・漫画のアプリ（`com.viewer.comicscreen`）・ホーム・最近使ったアプリで確かめた。

| 操作 | 届いた合図 | 届かなかった合図 |
| --- | --- | --- |
| 戻るジェスチャー（どのアプリでも） | 移った先の画面に応じた出来事（下の行） | キー入力は0件。キー入力を受け取る権限があっても、ジェスチャーの戻るはキーとして届かない |
| 漫画のアプリで戻る（一覧へ） | `TYPE_WINDOW_STATE_CHANGED`（`ListActivity`）、`TYPE_WINDOWS_CHANGED` | — |
| 漫画のページ送り | `TYPE_VIEW_SCROLLED`：横の移動量（dx=546、445 …）と項目の番号（1/22→2/22）。約0.1秒ごと | 画面の切り替わり（同じ画面の中の移動なので来ない） |
| Discordでアプリを開く | `TYPE_WINDOW_STATE_CHANGED`、`TYPE_WINDOWS_CHANGED` | — |
| Discordのアプリの中の画面移動 | `TYPE_VIEW_SELECTED`、`TYPE_WINDOW_CONTENT_CHANGED`、スクロールする一覧の項目数の変化（27件→51件） | `TYPE_WINDOW_STATE_CHANGED` |
| Discordのスクロール | `TYPE_VIEW_SCROLLED`：縦の移動量（dy=-1218、-918 …、画素）と見えている項目の範囲。約0.1秒ごと | — |
| ホーム・最近使ったアプリ | `TYPE_WINDOWS_CHANGED`、ランチャーと最近使ったアプリ（`googlequicksearchbox`）の `TYPE_WINDOW_STATE_CHANGED` | — |

- アプリの切り替え・ホーム・最近使ったアプリ・別の画面（Activity・ダイアログ）への移動は、`TYPE_WINDOW_STATE_CHANGED` と `TYPE_WINDOWS_CHANGED` で分かる。
- 1つの画面の中の移動は、アプリによって `TYPE_VIEW_SCROLLED`・`TYPE_VIEW_SELECTED` で分かるものと、分からないもの（Discordの画面移動）がある。分からない場合は、画素で確かめるしかない。

## 問い2：自分の重ね表示を写さずに画面を撮れるか

ユーザー補助の窓単位の撮影なら、自分の重ね表示を写さずに、前面のアプリの窓を撮れる。専用の描画面も写る。

| 撮り方 | 自分の重ね表示 | 専用の描画面（`SurfaceView`） | 1回の時間 | 必要なもの |
| --- | --- | --- | --- | --- |
| ユーザー補助の画面全体の撮影（`takeScreenshot`） | 写る（紫・水色とも全部） | 未確認 | 20〜60ms | ユーザー補助の撮影の権限 |
| ユーザー補助の窓単位の撮影（`takeScreenshotOfWindow`） | 写らない（紫・水色とも0） | 写る（画面の約93%が緑） | 20〜60ms | ユーザー補助の撮影の権限と窓の一覧の権限（`canRetrieveWindowContent`） |
| 画面共有（`MediaProjection`。本体の画面翻訳が使う） | 写る | 写る | — | 始めるたびの確認画面 |

Discord・漫画のアプリ・最近使ったアプリ・ランチャーの窓も、窓単位の撮影で真っ黒にならずに撮れた。本体がどの撮り方を使うかは `docs/設計/画面翻訳.md`。

## 問い3：ユーザー補助の撮影はどれくらいの間隔で撮れるか

ユーザー補助の撮影は、画面全体・窓単位とも約0.33秒に1回（1秒に3回）までである。前の撮影の終わりから空ける時間を変えて、8回ずつ撮った。

| 空ける時間 | 画面全体 | 窓単位 |
| --- | --- | --- |
| 0ms・100ms | 2回目以降の多くが失敗（コード3＝間隔が短い） | 同じ |
| 250ms | 8回とも成功（1回の時間を足して約0.36秒ごと） | 8回中2回失敗 |
| 330ms・400ms | 8回とも成功 | 8回とも成功 |

このため、約0.1秒おきに5枚撮って重ねる撮り方（動く画面のモード）はユーザー補助の撮影ではできない（5枚に約1.5秒かかる）。

## 問い4：スクロールの量が取れるか

`TYPE_VIEW_SCROLLED` で、移動量が画素で約0.1秒ごとに届く（Discordは縦の dy、漫画のアプリは横の dx）。

- 窓の中身を読まない権限（`canRetrieveWindowContent="false"`）でも、移動量は届く。本体のユーザー補助で、設定のアプリで dy=404 などが届いた。
- 動いていないスクロールの知らせも来る。Discordで一覧を組み直したときに dx=dy=0 が届いた。
- どの一覧がスクロールしたかは、窓の中身を読まない権限では分からない（出来事の窓の番号までは分かる）。

## 重ね表示と触れた操作

ふつうの重ね表示は、触れた操作を下のアプリへ通すと不透明度に上限がかかる。ユーザー補助の重ね表示にはかからない。本体の訳の枠で確かめた。

- Android 12以降、ほかのアプリの重ね表示（`TYPE_APPLICATION_OVERLAY`）を通り抜ける操作は、窓の不透明度がシステムの上限（`InputManager.maximumObscuringOpacityForTouch`、既定0.8）を超えると捨てられる。上限に合わせた窓では、下の原文がわずかに透ける。
- ユーザー補助の重ね表示（`TYPE_ACCESSIBILITY_OVERLAY`）は、不透明のまま触れた操作を下のアプリへ通せる。この窓は、ユーザー補助のサービスの `WindowManager` からしか置けない。
- ユーザー補助の重ね表示は、ふつうの重ね表示（浮遊ボタンのメニューなど）より手前に出る。

## プロセスの終わり方

OS が残す前回までの終わり方（`ApplicationExitInfo`）と、自分で預ける印（`setProcessStateSummary`）を、`featurelab` の `ExitLab` で確かめた（`adb shell am start -n app.plamotranslate.featurelab/.MainActivity --es exit <exception|kill|exit1|exit0|none>`）。不具合の記録（`docs/設計/アーキテクチャ.md`「不具合の記録」）はこれに依る。

| 終え方 | OS の記録（理由・状態・重要度） | 預けた印 |
| --- | --- | --- |
| 受け止められない例外 | `REASON_CRASH`・0・前面（100）。受け口が動いてから9ms後の時刻。「停止しました」を閉じると、同じ pid の2件目（`REASON_CRASH`・裏（400）、5.7秒後）が残る | 1件目には戻る。2件目には無い |
| `Process.killProcess(myPid())` | `REASON_SIGNALED`・9・前面（100） | 戻る（終える直前に預け直した印も戻る） |
| `exit(1)`／`exit(0)` | `REASON_EXIT_SELF`・1／0・前面（100） | 戻る |
| 強制停止（`am force-stop`） | `REASON_USER_REQUESTED`・0 | 戻る |

- 自分で `killProcess` すると、OS の記録は外から SIGKILL で止められたときと見分けがつかない。意図して終えたことは、終える直前に預け直す印で残す。
- 例外で1回落ちると、記録が2件になる。印と pid で同じプロセスとみなして1件にする。
- 前のプロセス（同じ UID）が出したログの行は、次のプロセスから `logcat -d` で読める。ただし REDMAGIC は既定でログを書かない（「設計に効く、思わぬ事実」）。

## 設計に効く、思わぬ事実

- **REDMAGICのゲーム支援がユーザー補助を切り離す**：ゲームを開いた直後（`cn.nubia.gameassist` が動いた後）、機能テストのアプリと本体の両方のユーザー補助が止められ、異常終了したサービスとして切り離されたままになった（`adb shell dumpsys accessibility` の `Crashed services`）。設定では有効のままで、アプリを更新するか、利用者がオフ・オンし直すまで戻らない。本体の知らせ方は `docs/設計/画面翻訳.md`。
- **切り離された状態は `am crash` で作れる**：`adb shell am crash app.plamotranslate` でアプリを異常終了させると、ユーザー補助が有効のまま `Crashed services` に入る。`am force-stop` では作れない。強制停止すると、Androidがユーザー補助を有効の一覧から外す（設定の値が空になる）。どちらの後も、利用者がオンにし直すまで戻らない。
- **有効なユーザー補助の書き方は2通りある**：`Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` には、完全な名前（`app.plamotranslate/app.plamotranslate.screen.OverlayAccessibilityService`）と短い名前（`app.plamotranslate/.screen.OverlayAccessibilityService`）のどちらかで書かれる。オン・オフし直した後は短い形になった。比べるときは `ComponentName` に戻す。
- **REDMAGICはログを黙らせている**：既定で `log.tag=S` になっており、アプリのログも異常終了の記録（`AndroidRuntime`）も出ない。アプリはログを自分のファイルにも書き、不具合の記録にはそちらを添える（`docs/設計/アーキテクチャ.md`「ログ」）。タグごとのプロパティ `log.tag.<タグ>` で開けられ、端末を再起動すると黙った状態に戻る（開け方は `docs/手順/開発環境.md`「ログを見る」）。
