# バックログ

製品の既知の問題、確かめていないこと、決まっていないことの一覧。各項目には、問題・未確認の事実・未決の問いと、その条件と根拠（コードや文書の場所）を書く。予定・順番・担当は書かない。解決した項目は消し、決まった事項は `docs/判断/` に1件足す。

## 既知の問題

### 画面翻訳

- **動く画面のモードで、スクロールの途中に訳し始めると枠がずれる**（作者の指摘）：枠の座標を数枚の中央値の画像（`FrameStack.median`）で決め、最後のコマに合わせていない。止まるのも最大3秒しか待たない（`SceneProfile.MOTION`）。Discord を動く画面のモードでスクロールしながら訳すと起きる。直し方の案は、数枚の間で画面全体がずれていたら重ねずに最後の1枚を使う、スクロールのイベントの移動量で枠を動かす（追従）。
- **横向きのゲームで思ったように訳されない**（作者の指摘）：縦で始めて横の画面へ移った回の撮影が「ステータスバー 107px」で、横で始めた回は0pxだった（端末のログ、2026-11-13）。ステータスバーより上は訳さないので、107pxと読むと横画面の上の約9%（タイトル・上端のメニュー）を捨てる。高さはサービスの Context の `currentWindowMetrics` から読んでいて（`statusBarHeight`）、全画面のアプリでも縦の値が返る疑いがある。縦で始めて横の全画面アプリへ移ったときに返る値は `featurelab` で確かめていない。症状が「上の文字が訳されない」「枠がずれる」「すぐ消える」のどれかも分かっていない。
- **一般の画面で目標の速さに届かない**：文字の多い画面は、文字認識に翻訳が加わり、要件の2秒に届かない（値は `docs/設計/画面翻訳.md`「性能の目安」）。大半は訳文の生成である。実際のアプリの画面での、ボタンから重ね表示までの通しの時間は測っていない。
- **訳す先を日本語に固定している**：要件の「訳文の出力先は設定で変えられる」が無く、`SCREEN_TARGET`（`screen/ScreenLanguage.kt`）で日本語に固定している。足すなら画面翻訳の設定と `TranslationStream` を開くときの訳す先だけを変え、状態遷移と判定器は変えない。
- **文字認識の読み落とし**：スマホ画面内の小さな横書き、縦の長音、「嘟」。白縁の文字で、最小値の画像の読みが正しくても点が同じだと置き換わらない（ML Kit の行の確信度を点に入れる案がある）。原文の言語の自動判定で、ローマ字の名前の一部をハングルとして拾う。
- **言語の違う隣の行が1つのブロックになる**：吹き出しのまとめ方（`BubbleGrouper`）は仮名の有無でしか分けない。文字種で分ける案がある。
- **訳文に別の文字（タイ文字など）が混ざる**：翻訳モデルの側の問題。頻度は数えていない。生成の点検（`TranslationChecks`）で弾いて訳し直す案がある。
- **評価の道具と材料が足りない**：評価の `BenchActivity` は吹き出しのまとめ方に決め打ちで、場面ごとのまとめ方を評価できない。実機の確認に使った Discord 風の画面と背景が動く画面は、リポジトリに無い。評価用の画像の状態は `docs/現在地.md`「既知の問題」。

### 会話翻訳

- **翻訳に会話の文脈を渡していない**：会話翻訳は文脈も履歴も渡さない（背景の `context` を渡すのはカメラ翻訳の表・メニューのモードだけ）。口は `TranslationStream.Options.context` にある。PFML3の履歴と用語集は組み立てていない。代名詞や省略の多い会話で訳が不自然になりうる。案は、方向別の履歴（3組）＋共通の文脈と、方向の違う履歴を混ぜる方式を訳文で比べる。途中訳のためのKVキャッシュの先頭の再利用（今は実行ごとに空にする）も関わる。
- **画面を離れるとマイクが止まる**：会話翻訳にフォアグラウンドサービスが無い（マニフェストに `foregroundServiceType="microphone"` のサービスが無い）。足しても翻訳の契約は変わらない。
- **テキスト翻訳の音声入力が区切りで止まる**：最初の確定で止まるので、言語の交代や長い発話の区切りが来ると、そこから後ろの音声を捨てる（コードから読んだもの。端末では確かめていない）。会話と同じ値の組（`SegmentationProfile`）を使っている。案は、「話し手の交代で区切るか」などを値の組に足し、音声入力の組を作って話し終わりまで続ける。
- **同じ言語どうしの会話は区切りがずれる**：話し手の交代を言語の変化で見分けるので、同じ言語の2人や、1人が言語を混ぜて話すと区切りがずれる。区切るボタンで補う。自動で見分けるなら、声の特徴（話者埋め込み）で話し手の交代を見る。
- **止めた・消した後の訳**：止めると持っていた途中の文字を捨て（`ConversationSession` の `Event.Stopped`）、消すと待っている確定訳を捨てる（`Event.Cleared`）。翻訳モデルが使えないときに途中訳を渡さない判断が、中核ではなく `ConversationViewModel` にある。
- **韓国語の認識結果の余分な空白**：SenseVoice が「생각 을 하 면서」のように語の途中に空白を入れる。`SenseVoiceRecognizer` は分かち書きが正しい場合もあるので韓国語の空白を触らない。訳への影響は小さい。
- **Qwen3-ASR を選んだときの手触り**：書き起こしが重い（5秒の発話に1〜2秒）ので、文ごとに書き起こしてつなぐ。試用で次が残った。
  - 確定したカードの「認識」の時間が、つないだだけのときは0msになる。
  - 話し終わりの直前の短い文（「ね」など）が落ちることがある。0.4秒未満の文は文として書き起こさず、話し終わりで残りとして書き起こすが、残りが0.25秒未満なら書き起こさない（`SpeechSegmenter` の `MIN_REST_SAMPLES`）。
- **相手を自動にすると、弱い判定1回で相手の言語が決まり、会話の終わりまで残る**：相手不明の間、`SpeakerJudge` は自分以外の言語の確率の合計をしきい値と比べるので、候補の多いモデルでは相手に傾き、相手は1回の確定で決まる。録音のリプレイで、最初の2秒の英語「OK.」を韓国語（0.55）と判定し、以後の英語を韓国語として書き起こした。日本語と英語の混ざった文を Whisper tiny が韓国語0.70と判定した例もある。直すなら相手を決める側で、判定器が「相手（言語は未定）」を返し分け、相手の言語は言語の確かな相手の発話だけで決める（判定器と音声の出来事の約束が変わる。[改善の一巡で足した決まりを原因の層で見直す](判断/2026-11-15_改善の一巡で足した決まりを原因の層で見直す.md)）。
- **区間の判定が言語を誤ると、間違った位置で区切り、短い断片のカードができる**：SenseVoice は、ある韓国語の話し手の1.5秒の区間の約4割を日本語と判定する。訳す向きはカードの書き起こしの言語で直るが、区切りは区間の判定で決めるので残る（「哼。」のような1秒前後のカード、文の途中での区切り）。Whisper tiny を足して2つがそろったときだけ決める案は、作者の日本語を Whisper tiny が7割韓国語とするので採らなかった（[会話のカードの言語を書き起こしの言語と利用者の指定でも決める](判断/2026-11-19_会話のカードの言語を書き起こしの言語と利用者の指定でも決める.md)）。
- **繁体字で北京語を話す相手のカードを入れ替えると、広東語として書き起こす**：SenseVoice の入れ替えの書き起こし直しは、繁体字の中国語を広東語（`yue`）として指定する（`SenseVoiceRecognizer.languageCode`）。台湾などの北京語の話し手で確かめていない。直すなら、相手の言語に北京語（繁体字）と広東語を分ける。
- **Qwen3-ASR では、カードの書き起こしの言語で表示の言語を直せない**：Qwen3-ASR は言語を指定して書き起こすので、書き起こしの言語は根拠にならず、話し手は Whisper tiny の区間の判定だけで決まる。同じ録音の PC の判定で、Whisper tiny は作者の日本語の1.5秒の区間の約7割を韓国語とした。Qwen3-ASR で日本語と韓国語の会話を確かめていない。
- **短い文1つでカードの話し手が確かになり、続く交代の境界が遅れる**：区間の根拠の無い1秒ほどの文の全体の判定1回で、カードの話し手が確かになる（PC のリプレイで1件。端末では見ていない）。1回の判定では決めない決まりを文の全体にも広げるかは、間を空けた短い返事を区切る役目と合わせて決める。

### カメラ翻訳

- **赤い見出しの帯が直前の項目と同じ段落になる**。
- **崩れた読み取りに残る弱さ**：パッケージのロゴのような飾り文字で、区切りの付いたり離れたりが続く（作者は許せる程度とした。[カメラ翻訳の区切りと原文を直近のコマの多数決で安定させる](判断/2026-11-13_カメラ翻訳の区切りと原文を直近のコマの多数決で安定させる.md)）。使っていない手は、認識器の確信度を票の重みにする（`OcrLine` に確信度を足す `core-ocr` の契約の変更。ML Kit が行・文字の確信度を返すかは `featurelab` で確かめていない）、カメラの動きの補正、小さく写った文字を拡大して読み直す。実機の読み取りの列を記録して PC で中核の追跡・多数決・区切りにリプレイする仕組みは無い。手がかりの弱い調整は、1台の端末と手元の数場面に合わせ込みやすい。
- **画面が動いていなくても読む間隔が変わらない**：見えている段落がすべて確かで画面がほとんど動いていないときも、同じ間隔で読む。電池に効く。読む間隔を延ばし、動いたらすぐ戻す案がある（画面翻訳の `ScreenChange` を使える）。

### 共通

- **GPUでの翻訳の途中で落ちると、CPUへ切り替わらない**：切り替えは読み込みから初回の推論までに落ちたときだけである（`docs/設計/翻訳コア.md`「GPUで落ちたときの切り替え」）。GPU の推論はアプリと同じプロセスなので、GPU 側で落ちると画面ごと終わる。GPU の推論を別のプロセスに分ければ、画面を残して CPU で読み直せる。そのときは、サービスが終わったときの通知と画面の生存を `featurelab` で確かめ、`JobEngine` の裏で依頼・途中訳・取消・終了の扱いを設計する必要がある。端末全体のメモリ不足で画面のプロセスも終わる場合は、分けても防げない。
- **「ライセンス」のページに Qwen3-ASR と Whisper tiny が無い**：ページのモデルの一覧（`AboutApp.kt` の `MODELS`）は、ダウンロードの一覧（`ModelCatalog`）と別に手で書いている。0.8.0 では韓国語の文字認識のモデルが漏れ、今は Qwen3-ASR 0.6B と Whisper tiny が漏れている。ONNX Runtime の用途も「文字認識の実行」だけで、言語の識別を書いていない。防ぐ仕組みは「ライセンス文を集め直す」の手順（`docs/手順/開発環境.md`）だけである。`ModelCatalog` の組ごとに表示（名前・作者・ライセンス・元のモデル・全文）への参照を持たせ、参照の無い組があれば止まる形にすれば防げる。
- **APKが大きい**：大きさは `docs/設計/アーキテクチャ.md`「APKの中身」。ONNX Runtime が漫画用OCR（`onnxruntime-android`）とsherpa-onnxのAAR（静的に組み込み）の2か所に入っている。1つにまとめるのが一番効く。llama.cppのCPUの版（`GGML_CPU_ALL_VARIANTS` で世代ごとに全部作る）から古い世代を外す手もある。

## 実機で未確認のこと

単体テストとビルドまでで、実機ではまだ見ていないもの。

- **クイック設定のタイルをロック中に押したとき**（カメラ翻訳・会話翻訳のタイル）：ロックを解いてから画面を開くか。ロックを解かずにカメラやマイクの画面が開くなら、TileService の unlockAndRun で包む必要がある。
- **トップ画面を横向きにしたとき**：タイルを名前と大きなアイコンだけにした今の形で、名前が切れないか。
- **画面翻訳のフローティングボタンとメニューの見た目**：アプリのロゴにプライマリカラーの縁、自動のときの外側の輪、原文の言語のバッジ（`OverlayViews.kt` の `FloatingButton`）と、メニューの選択肢の折り返し（`WrapLayout`）を、ライトとダークの両方で。画面翻訳を動かしたまま端末のダークモードを切り替えたとき、サービスに `onConfigurationChanged` が届いてフローティングボタンが塗り直されるか（`docs/資料/端末の能力.md` にまだ無い）。
- **会話のカードの色**：夜の鳥の役割の面（ローズ・青緑）で、自分と相手のカードの文字が読みやすいか。
- **カメラ翻訳で訳す先を日本語以外にしたとき**：原文に日本語を選んで、日本語の行を読んで訳すか。訳す先を英語にすると日本語の行を訳し、韓国語にするとハングルの行を訳さない（0.5.0の修正）。
- **会話翻訳で対面と1画面を切り替えたとき**：一覧が末尾から出るか（0.5.0の修正）。
- **読み上げのモデルを取っている間の画面**：取っている間にトップ画面へ戻って使えるか。`ReadAloud` は一度読んだモデルを手放さないので、確かめるにはアプリを止め（`adb shell am force-stop app.plamotranslate`）、`/sdcard/Android/data/app.plamotranslate/files/models/tts/supertonic-3` を消してから設定の画面で取り直す。
- **版を上げて足りないモデルが増えたときの画面**：0.8.0で韓国語の文字認識のモデルを足したとき、初回と同じ文面とライセンスの説明が出て、上げた人には分かりにくかった。モデルを選んで取る今の「モデルの準備」の画面で、上げた人にどう見えるか。
- **自分の言語・訳す先の言語を日本語以外にしたとき**：会話翻訳で自分を日本語以外にしたときの訳す方向、カメラ翻訳で訳す先を日本語以外にしたときの訳、テキスト翻訳の音声入力。ベトナム語の声調記号・広東語の口語の字の訳の質。
- **ラテン文字で書く英語以外の言語**：ML Kit の英字の認識器が、ベトナム語の声調記号などをどこまで読めるか。英語と同じ正規化（`EnglishText`）でドイツ語の名詞の大文字が小文字になる影響。カメラ翻訳と画面翻訳で同じ。
- **英語の漫画の画面翻訳**：実機で見ておらず、評価の正解も無い。
- **画面翻訳の場面とまとめ方**：ゲームの場面は実機で確かめた。チャット・漫画の場面と文章のまとめ方は、評価でも実機でも見ていない（チャットの場面で段落ごとに訳されるか、漫画の場面で吹き出しいっぱいに広がるか）。
- **カメラ翻訳の番号の点を落とした行**：項目が分かれない問題を直した版。
- **動く画面のモードで訳す文字が無いとき**：自動で訳す設定で「訳す文字なし」になると、判定Bは規則1（画面の切り替わり）しか効かず、待ちに戻りにくいおそれがある（コードから読んだ懸念）。文字の無い場面から文字のある場面へ移ったときに訳し始めるか。
- **Qwen3-ASR がヒンディー語をローマ字で書くことがあるか**。
- **音声認識が依存する端末の振る舞いを `docs/資料/端末の能力.md` に書いていない**：sherpa-onnx の認識器を、作ったスレッドと別のスレッド（認識のワーカー）から呼べること。2つの ONNX Runtime（sherpa-onnx に組み込まれた分と `onnxruntime-android`）を1つのプロセスで動かして落ちないこと。会話翻訳の試用では動いているが、確かめた条件として書いていない。
- **会話翻訳の新しいカードの頭の語の欠け**：試験音声で韓国語の頭の「조금」が欠けた。実際の声で起きるか。
- **端末の能力の残り**（`docs/資料/端末の能力.md`「確かめていないこと」）：ユーザー補助の画面全体の撮影で専用の描画面が写るか。実際のゲームで、ゲーム支援が切り離したときに本体が知らせるか、ウィンドウ単位の撮影でゲームの画面が写るか。3ボタン操作の端末で戻るがキーとして届くか。REDMAGIC 11 Pro 以外の端末で、同じイベントが届き、同じように撮れるか。
- **ほかの端末で動くか**：確かめたのはREDMAGIC 11 Pro（GPU）と15T Pro（CPU）だけ。
  - Snapdragonの1〜2世代前（Adreno 740・750）でGPUが動くか。読み込めても訳文が崩れるなら、機種を見てCPUに切り替える必要がある。
  - GPUでの初期化に失敗する端末で、CPUへの切り替えと更新後の維持が働くか。終了理由は診断ZIPとシステムログで切り分ける（`docs/設計/翻訳コア.md`「GPUで落ちたときの切り替え」）。
  - 15T Proで会話の画面を何度か開閉して、強制終了（0.3.3で直した）が起きないか。
  - 遅い端末で、設定の「性能」の既定の決め方が合うか（`docs/設計/翻訳コア.md`「性能の設定」）。CPUの端末で途中訳が遅れないか。
- **大きな画面での縦向き固定**：会話翻訳とカメラ翻訳は `screenOrientation="portrait"` だが、targetSdk 36のアプリは、Android 16の大きな画面（短辺600dp以上）では縦向き固定が効かない。カメラ翻訳の座標の計算（`CameraGeometry`）は縦向きの前提なので、横向きで枠がずれるおそれがある。

## 測っていないこと

- **画面翻訳の韓国語のPP-OCRの確信度の下限**：0.8（`ChoicePolicy.PADDLE_KO_MIN_CONFIDENCE`）は画面1枚で決めた。韓国語の評価の画面の分布で確かめていない。トリッカルの画面（ゲームの場面・韓国語）では問題無く訳せ、2重の行も出なかった（実機）。文字認識の時間は測っていない。
- **カメラ翻訳で一時停止から見えている訳がそろうまで**：2Bで約8秒（4件、2026-11-06）は、4件ずつ1本のシーケンスで訳していた頃の値。空いた分だけ選んで渡す今の作りでは測っていない。
- **会話中のCPUの取り合い**：音声認識（CPU）と翻訳（GPU、CPUの端末ではCPU）が同時に動く。Qwen3-ASR は6スレッドを使う。MediaTek など CPU だけの端末で、認識の遅れ（話し中のカードの秒数）と翻訳の速さを測っていない。書き起こしのスレッド数（2・4・6・8）ごとの処理時間を、途中訳を止めた場合と比べていない（Qwen3-ASR は4と6だけ測った）。
- **会話翻訳の応答の速さ**：短い文（2〜3秒）での、話し始めから最初の文字までと話し終わりから確定までの時間。カードの言語を決める長さ（0.8〜2.0秒）ごとのカードの言語の正解率。VAD の値を変えたときの話し始めの検出の遅れ。ONNX Runtime で直接動かす Whisper tiny の識別1回の時間（`docs/設計/会話翻訳.md`「性能の目安」）。値は詳細設定の「音声認識の調整」で変えられ、ジョブごとの時間はログに出る（`docs/設計/会話翻訳.md`「動作確認」）。
- **話し手のしきい値の根拠**：`SpeakerJudge.WINDOW`（0.75）・`PHRASE`（0.6）を、実機の区間と文の全体のスコアの分布で確かめていない。相手を決める確定だけしきい値を上げるかも、分布を見て決める。
- **メモリ**：0.8Bでモデルに合わせて1GB弱を使い、6GB以上を目安にしている（目安は実機で確かめていない）。2Bはさらに1GB余り要る見込み。コンテキスト4096・シーケンス8本のときのアプリのメモリも測っていない。
- **SenseVoice の言語を固定した認識器**：カードの言語を入れ替えて書き起こし直す最初の1回に読み込む認識器（約240MB）の、読み込みの時間とメモリの増え方を測っていない。翻訳モデル 2B と同時に載ったときの余裕も見ていない。結果で、使い終わったら解放するかを決める。
- **長時間の連続稼働での発熱**：会話翻訳の30分の連続稼働を測っていない（要件の「連続稼働」）。REDMAGICの冷却ファンを有効にした状態でも測っていない。

## 構造の既知の問題

設計の幹（`docs/設計/アーキテクチャ.md`「設計の原則」）から外れている箇所。直すときの進め方は `CLAUDE.md`「変更の進め方」。

- **文字認識の位置の判断が Android の型に依存する**：行の突き合わせ（`BlockMerger` の手順1・2）と列（`VerticalColumns`）が `android.graphics.Rect` で位置を比べるので、縦書きの先取り・韓国語へ譲る・重なる行を捨てる、を単体テストで確かめられない。直すなら `core-ocr` に自前の矩形の型を置き、`Rect` との変換を認識器の側に寄せる。`Geometry` とカメラ翻訳の行の追跡にも及ぶ。
- **`EngineHolder` が画面と結び付いている**：`object` のままで、画面（`ModelSwitch`・`SettingsActivity`・`PerformanceSettings`・`MainActivity`・`CameraTranslateActivity`）とサービスが `select`・`selected`・`ensureLoaded`・`reload` を直接呼ぶ。単体テストするには翻訳エンジンの読み込み（JNI）を差し替えるインターフェースが要り、呼ぶ側の書き換えも広い。翻訳の契約を迂回している残りの3か所もここから来ているので、一緒に直す：`LiveTranslator` がエンジンを直接受け取って同じものかを見ている。`ScreenTranslateService` がモデル名のために `EngineHolder.awaitReady` を別に呼んでいる。`BenchActivity` が `Translations.open` を通らずにストリームを作っている。
- **`ReadAloud` の残り**：`ConversationViewModel` が `ReadAloud.isAudible()` を直接呼ぶ（`Flow` にするなら、読み終わりから400msマイクを無音にする判定も作り直すので、反響を実機で確かめる必要がある）。失敗の `Toast` が画面の外にある。使わないときに読み上げのモデル（約220MB）を手放す時機は決めていない。
- **`CameraTranslateActivity`（約410行）が CameraX の準備を持つ**：`startCamera`・`toUprightBitmap` が画面の中にある。外すと CameraX の動きが変わりうる。
- **画面翻訳のサービスに撮影・イベント・訳の枠が集まっている**：`ScreenTranslateService`（約660行、設計の点検で行数の注意が出る）が、監視（`watch`）、のぞき（`peek`）、作業の実行（`capture`・`recognize`・`translate`）、ユーザー補助が切れたことの表示、モデルの切り替えを持つ。メニューの行（`ScreenMenuEntries`）と1回の翻訳のデータ（`ScreenWork`）は分けてある。状態遷移の作業（`Effect`）を受けて実行する部品ごとに、命令と購読の形で分ければ解ける。外すと撮影と監視の時機が変わる。
- **訳の枠のウィンドウを置けなかったことが状態遷移へ届かない**：`TranslationOverlay.show` でウィンドウを置けないと、枠が1つも出ないまま訳し終えて件数と時間を出す。置けないのは重ね表示の許可を途中で外したときなどに限られる。置けなかったことを返り値の無い命令でイベントとして出せば、`ScreenSession.reduce` の出来事として取り消すかを決められる。
- **カメラ翻訳の訳の対応表**：`CameraSession` の `translated`（原文のキーごとの確定した訳）は、契約のキャッシュの層ではなく、段落へ訳を当てる表示の状態である。契約の1次のキャッシュへは寄せない（コマごとに同期で引く口が契約に無い、チャンクと段落で粒度が違う、似ている判定は画面翻訳の完全一致と合わない、の3つで情報が切れる）。残る問題は次の2つ。
  - モデルを切り替えたとき、対応表は確定した訳を全部捨てる。契約のキャッシュは捨てずに品質で選ぶので、扱いがそろっていない。
  - 読み揺れの吸収（`TextSimilarity.similar`）が、追跡と多数決（`LineTracker`）と対応表の引き方（`CameraSession`）の2か所にある。文字ごとの多数決で原文が落ち着くので、対応表は完全一致に近づけられる見込みがある。
- **試験の足りないところ**：`TranslationStreamTest` に `onTooLong` から1本で訳し直して空にする経路。`SqlitePersistentCache` が古い世代の `store` を書かないこと（中核の試験は渡す世代しか見ない。計装試験が要る）。`SpeechPipeline` のジョブを捨てる・始め直す（`reset`）場合（スレッドを使うので、捨てる判断は `RecognitionQueueTest`・`UtteranceRetentionTest` で守っている）。
- **中核へ移していない判定**：撮った1枚が使えるかなど、Android の側に残っている判定（`docs/設計/アーキテクチャ.md`「判定の一覧」）。
- **読み上げのステップ数・スレッドの定数**：`SupertonicSpeaker` の `DEFAULT_STEPS`（8）・`NUM_THREADS`（4）は、REDMAGICでの計測に基づく定数で、翻訳の「性能」のように設定と計測の画面から変えられない。
- **カメラ翻訳の一時停止と設定の変化のイベントが散っている**（0.10.0の前の設計のレビュー）：一時停止を `LiveTranslator.paused` と `CameraSession.paused` の2か所で持つ。同時に訳す数の変化を毎コマ調べて `IntakeChanged` を送り、エンジンの変化は別の購読から送る。原文と訳す先が同じなら原文を自動に戻す判断を `CameraTranslateActivity` が持ち、ストリームの開き直しが2回続く。実機で比べる数え上げ（`CameraSession` の submitted など）も散っている。
- **`SpeechSegmenter` が大きい**：約800行。文ごとに書き起こしてつなぐ部分と、出来事をカードの順に出す仕組みが、区切りの状態遷移と同じファイルにある。モデルの性質（書き起こしが重いか）の分岐も状態遷移に散っている。話し手の時系列（`SpeakerTrack`）へ移せる残りは、次のカードの話し手（言語と確かか）の引き継ぎ、確かめの結果が古いかの判断、言語が決まらないときの仮の言語。判定（`SpeakerTrack.Verdict`）は、入口ごとの型に分けるか、実行を1か所にする。
- **会話翻訳の制御の残り**：区切るボタンの書き起こし待ちを、画面（`ConversationSession.queued`）と認識（`SpeechSegmenter`）が別々に数えている（出来事にカードの番号を持たせれば対応する。音声認識の契約に及ぶ）。止める順番（`Flushed` を待ってから止まる）を `ConversationViewModel` が持つ。
- **認識のジョブの無駄と追い越し**：話し中の交代で区切った後、移す文を足す前に新しいカードの途中結果を頼み、捨てている（`SpeechSegmenter.cutAt` から `langChanged`。重い書き起こし1回分）。後ろのカードの区切った残りの書き起こし（`FINAL`）が、前のカードの文の書き起こし（`PHRASE`）より先に処理されるので、前のカードの確定が待たされる（出来事はカードの順に出すので順は崩れない）。
- **判定なしで、話した人は分かるが言語が決まらない文**：相手不明（自動）で、言語の判定の無い文が相手の候補のいくつかに同じだけ合う（Qwen3-ASR で英語・フランス語などのラテン文字の文）と、言語を当てられないので自分の発話として扱う。相手の発話で言語は未定、という向きを表すには `Direction`（原文の言語が必ずある）と会話の中核の契約を変える必要がある。以前は英語と決め打ちして相手を英語に固定していた。
- **SenseVoice の言語を固定した認識器を、書き起こしのワーカーで読み込む**：初めて書き起こし直すとき、確定に要るジョブがその読み込みの間待たされる（時間は測っていない。「測っていないこと」）。遅れが問題なら、読み込みを別のスレッドで先に行う。
- **PC のリプレイを SenseVoice で流すと落ちる**：`ConversationReplayTest.replay` を `PLAMO_REPLAY_MODEL=SENSE_VOICE` で流すと、sherpa-onnx 2.0.1 の Windows 版 JNI が SenseVoice の認識器を作るところ（sherpa-onnx の Kotlin の `OfflineRecognizer` がネイティブの認識器を作る呼び出し）でアクセス違反を起こし、テストの JVM ごと落ちる。端末では同じ認識器が動く。原因は調べていない。SenseVoice の区切りは、端末で録音を `--es wav` で流して確かめる（`docs/設計/会話翻訳.md`「動作確認」）。
- **リプレイが `SpeechPipeline` を書き写している**：`ConversationReplayTest` がジョブの取り出しと結果の届け方を写している。`SpeechPipeline` に時計と実行の仕方を差し込む口を作れば共通にできる。端末の処理時間の式（`DeviceTiming`）の元の記録が手順に無い。手で区切った位置は端末の記録から渡すので、操作（区切る・相手を選ぶ）の時刻は録音と一緒に残していない。

## 決まっていないこと

- **原文の言語が自動のときに PP-OCR 韓国語を使うか**：中国語・日本語の行の選び方に効く。中国語・日本語・韓国語の評価の画面で前後を比べていない。
- **ウィンドウ単位の撮影を入れるか**：ユーザー補助で訳の枠を写さずに前面のアプリのウィンドウを撮れば、判定Bの取り消しの誤りが減る。入れるには、ユーザー補助にウィンドウの一覧と撮影の権限を足し、利用者に有効化をやり直してもらう必要がある（[ウィンドウ単位の撮影は今は入れない](判断/2026-11-12_ウィンドウ単位の撮影は今は入れない.md)、`docs/資料/端末の能力.md`）。
- **画像を直接読んで訳す視覚言語モデル**：OCRの読み落としが専用OCRでも直らないときに、今の組み合わせと比べるか（[視覚言語モデルは最初は採らない](判断/2026-11-06_視覚言語モデルは最初は採らない.md)）。
- **ユーザー補助のスクロールの扱い**：ユーザー補助のスクロールを `Invalidated` に畳むので、タップで訳すときも、利用者が操作していないスクロール（チャットの自動スクロールなど）で訳が消える。規則3を自動で訳すときだけにした方針とぶつかる。意図どおりかは決まっていない。変えるなら、出来事を「ウィンドウが変わった」と「スクロールした」に分けて始め方ごとの扱いを `reduce` で決める。`com.android.systemui` のスクロールを除く前提は `docs/資料/端末の能力.md` に無い（通知の引き出しの出来事は `featurelab` で確かめていない）。
- **会話の履歴をアプリ内で見返す画面**：今は会話ログの共有とMarkdownでの保存で代えている（[会話ログは共有とMarkdownの保存にしアプリ内に残さない](判断/2026-11-06_会話ログは共有とMarkdownの保存にしアプリ内に残さない.md)）。
- **Qwen3-ASR を選んだとき、日・韓・英・中の発話を SenseVoice へ振り分けるか**：書き起こしの重さは減るが、メモリが増え、音声認識モデルを前もって選ぶ形から外れる。
- **会話翻訳の相手の決め方の残り**：
  - 自動で決まった相手を、「会話を消す」で忘れるか（今は忘れない。`ConversationSession` の `Event.Cleared` は発話だけを消す）。
  - 相手を選び直したときの自分の発話の訳し直しを、新しい発話の確定訳より後ろにするか、件数に上限を置くか。
  - 自分が日本語なら、相手不明の候補から中国語を外している（逆も同じ）。中国語が候補になった文を自分の言語でも書き起こして仮名を見る案は入れていない。中国語の音声を日本語の指定で書き起こしても仮名が出るかは確かめていない。
- **音声認識の出来事を分けるか**：「境界と話し手」「文の確定の文字」「カードの閉じ」に分ける形は入れていない（今の出来事でも、文の確定の文字は途中結果のつなぎで先に出る）。
- **Qwen3-ASR の役の名前を出どころで止めるか**：話していない短い音声を書き起こしに出していることを止められるか（短い返事は落とさない）。今は認識器の実装が観測した書き方だけを空にする。
- **「詳しい記録を残す」をオフにしたときの、それまでの記録**：利用者の文を含むログと `asr-rec/` の音声を消すか、知らせるか。
- **ほかの音声認識エンジン**：Nemotron 3.5 ASR Streaming と比べていない。多言語版のONNX（有志の書き出しと onnx-community 版がある）がsherpa-onnxのストリーミング認識で動くかも確かめていない。
- **Hexagon NPU**：使っていない（[HexagonのNPUは後回しにする](判断/2026-11-05_HexagonのNPUは後回しにする.md)）。GPUで目標の速さに届かない端末が出たときの選択肢として残る。

- **画面翻訳の評価で重く見る漫画の言語**：これまで中国語・韓国語・英語の漫画で評価した。
- **商用で配る場合の条件**：PLaMoの商用の条件と、SenseVoiceのモデルライセンス（FunASR）の本文は確かめていない（[無料のアプリでのPLaMoの利用は非商用の範囲とみる](判断/2026-11-06_無料のアプリでのPLaMoの利用は非商用の範囲とみる.md)）。
