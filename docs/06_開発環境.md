# 開発環境

更新日：2026-11-08

WindowsのPCで開発し、端末へUSBのadbで入れて試す（ワイヤレスadbも使える）。作者はREDMAGIC 11 Pro（Snapdragon 8 Elite Gen 5）と、MediaTekの端末（Dimensity 9400+）で試している。

## PCに入れるもの

| ソフト | 版・設定 | 用途 |
| --- | --- | --- |
| JDK | 17以上（AGP 8.13の要件）。Android Studio同梱のJBR 25はGradle 8.14.3が対応していないので使わない | Gradle |
| Android SDK Platform | API 36（Android 16） | `compileSdk` / `targetSdk` |
| NDK | r28以降（`ndk;29.0.14206865` で確かめた）。r28以降は16KBページサイズ対応の配置が既定になる | llama.cpp・JNIのビルド |
| CMake・Ninja | `cmake;3.31.6` | ネイティブビルド |
| Git | 最新版 | submoduleを使う |
| Python 3 | 任意 | ビルド中のスクリプトと評価の採点。`huggingface_hub` があればモデルの取得（`hf download`）にも使える |

Android Studioがあれば、SDK Managerで上の部品を入れる。Android Studioを入れない場合は、Android SDK コマンドラインツール（https://developer.android.com/studio#command-line-tools-only ）を `%LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest` へ展開し、`sdkmanager` で `platform-tools`・`platforms;android-36`・`build-tools`・`ndk`・`cmake` を入れる。環境変数はユーザー単位で `JAVA_HOME`、`ANDROID_HOME` を設定し、`platform-tools` を `PATH` に足す。

- PowerShellから `sdkmanager.bat` を呼ぶときは、パッケージ名を `'"ndk;29.0.14206865"'` のように引用符ごと渡す（引用しないとcmdが `;` で引数を割り、「Package ndk not found」になる）。
- `local.properties` に `sdk.dir` を書き、ビルドの前に `$env:PYTHONUTF8="1"` を設定する。
- **TLS検査のあるネットワーク**：Java標準の証明書ストアで `PKIX path building failed` になる場合は、Javaに Windows の証明書ストアを使わせる。`sdkmanager` は `$env:SDKMANAGER_OPTS="-Djavax.net.ssl.trustStoreType=Windows-ROOT"` を付けて実行し、Gradleは `%USERPROFILE%\.gradle\gradle.properties` に `systemProp.javax.net.ssl.trustStoreType=Windows-ROOT` を書く。プロキシを通る場合は、同じファイルに `systemProp.https.proxyHost` と `systemProp.https.proxyPort` を書き、`hf` コマンドには環境変数 `HTTPS_PROXY` を設定する。
- **デバッグ用の鍵はPCごとに違う**：開発版はPCごとのデバッグ鍵（`%USERPROFILE%\.android\debug.keystore`）で署名されるので、別のPCで入れた開発版には上書きできない（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。複数のPCから入れるなら、同じ `debug.keystore` を各PCの同じ場所へ写す（Gitには入れない）。写さずに入れ直すとアプリのデータ（設定・モデル）が消えるので、モデルを `/sdcard` などへ退避してから行う。

## 端末の準備

1. 設定の「端末情報」でビルド番号を7回タップし、開発者向けオプションを有効にする。
2. 開発者向けオプションで「USBデバッグ」と「ワイヤレスデバッグ」を有効にする。
3. PCと端末を同じWi-Fiにつなぎ、ワイヤレスデバッグの「ペア設定コードによるデバイスのペア設定」から次を実行する。

```text
adb pair <端末のIP>:<ペア設定用ポート>
adb connect <端末のIP>:<接続用ポート>
adb devices
```

Wi-Fiで端末同士の通信が遮断される場合は、USBケーブルでつなぐ。

## リポジトリ

GitHubのリポジトリ [kagerouttepaso/PlamoTranslate](https://github.com/kagerouttepaso/PlamoTranslate) に置いている（ブランチは `main`）。新しく始めるときは、サブモジュールごと取得し、Gitに入れていないsherpa-onnxのAARとモデルを取ってくる。

```powershell
git clone --recurse-submodules https://github.com/kagerouttepaso/PlamoTranslate.git
cd PlamoTranslate
# コミットの作者をGitHubのnoreplyのアドレスにする（このクローンだけの設定。.git/config に入る）
git config user.name kagerouttepaso
git config user.email 4670521+kagerouttepaso@users.noreply.github.com
./tools/get-sherpa-onnx.ps1 -Models   # sherpa-onnxのAARと音声認識のモデル
```

公開リポジトリなので、コミットの作者に勤務先などのアドレスを残さない（`CLAUDE.md`「公開リポジトリに入れないもの」）。PCのグローバル設定が勤務先のアドレスでも、クローンごとの設定（`.git/config`）が優先される。Gitは安全のため、リポジトリに入れたファイルから設定を自動では読まないので、クローンするたびに上の2行を流す。設定できているかは `git config --show-origin user.email` で確かめる（`file:.git/config` と出ればよい）。

翻訳モデルと漫画用OCRのモデルは「モデルの取得と置き場」の手順で取る。

最初に作ったときの手順：

```text
git init
git submodule add https://github.com/ggml-org/llama.cpp third_party/llama.cpp
git -C third_party/llama.cpp checkout <固定するコミット>
```

固定したコミットは `docs/00_現在地.md` の「固定した版」に書く。パッケージ名は `app.plamotranslate` を仮置きとし、変える場合は着手前に決める。

`.gitignore` で、重み（`*.gguf`・`*.onnx` など）、`models/`、sherpa-onnxのAAR（`third_party/sherpa-onnx/`）、テスト音声（作者の声を含む）、評価用のスクリーンショット `tools/testdata/ocr/`（漫画など著作物を含む）、ビルド出力をGitから外している。

## イテレーション0：llama.cppのCLIを端末で動かす

アプリを作る前に、llama.cppのコマンドを端末で直接動かして速度を測る。手順はllama.cppの `docs/android.md` の最新版を優先する。

2026-11-05に実際に通したビルド（PowerShell）。SDK同梱のCMake・Ninjaを使う。

```powershell
$s="$env:LOCALAPPDATA\Android\Sdk"; $cm="$s\cmake\3.31.6\bin"
& "$cm\cmake.exe" -S third_party/llama.cpp -B build-android -G Ninja "-DCMAKE_MAKE_PROGRAM=$cm\ninja.exe" `
  "-DCMAKE_TOOLCHAIN_FILE=$s/ndk/29.0.14206865/build/cmake/android.toolchain.cmake" `
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-28 -DCMAKE_BUILD_TYPE=Release `
  -DGGML_NATIVE=OFF -DGGML_OPENMP=OFF -DGGML_LLAMAFILE=OFF -DLLAMA_OPENSSL=OFF `
  -DGGML_CPU_KLEIDIAI=ON -DBUILD_SHARED_LIBS=OFF -DLLAMA_BUILD_TESTS=OFF
& "$cm\cmake.exe" --build build-android -j 12 --target llama-cli llama-bench llama-completion
```

端末への転送・翻訳・速度計測は `tools/device-translate.ps1` で行う（`-Bench` で `llama-bench`）。CLIとモデルを端末の `/data/local/tmp/plamo/` へ送って動かす。測り終えたら消す（「端末の片付け」）。

## モデルの取得と置き場

2026-11-06から、アプリが初回起動時に全画面の「モデルの準備」でモデルをダウンロードする（取得元・照合のハッシュは `app/.../models/ModelCatalog.kt`、仕組みは `docs/02_アーキテクチャ.md`「モデルのダウンロード」）。配った端末ではこれだけでよい。開発中は、下の手順でPCに取ったモデルをadbで送ってもよい（同じ名前・同じ版なら、アプリはダウンロード済みとみなす）。

| モデル | 取得元 | 端末内の置き場 |
| --- | --- | --- |
| PLaMo 3 Translate 0.8B（Q4_K_M、Q4_0） | Hugging Face `pfnet/plamo-3-translate-0.8b-GGUF` | `/sdcard/Android/data/app.plamotranslate/files/models/llm/` |
| PLaMo 3 Translate 2B（Q4_K_M、選んだときだけ） | Hugging Face `pfnet/plamo-3-translate-2b-GGUF`。ふだんはアプリの設定の画面の「2Bをダウンロード」で取る | 同上（`plamo-3-translate-2b-Q4_K_M.gguf`） |
| 音声認識（SenseVoice Small int8、Silero VAD） | sherpa-onnxのリリース（`tools/get-sherpa-onnx.ps1 -Models`）。下の対応で置く | `.../files/models/asr/` |
| 漫画用OCR（PP-OCRv6 manga） | Hugging Face `Kellenok/PP-OCRv6_manga`。下の対応で名前を変えて置く | `.../files/models/ocr/manga/` |
| ML Kit | アプリに同梱（モデル同梱版の依存関係） | 不要 |

```text
hf download pfnet/plamo-3-translate-0.8b-GGUF plamo-3-translate-0.8b-Q4_K_M.gguf --local-dir models
adb push models/plamo-3-translate-0.8b-Q4_K_M.gguf /sdcard/Android/data/app.plamotranslate/files/models/llm/
adb push models/ocr/manga/. /sdcard/Android/data/app.plamotranslate/files/models/ocr/manga/
```

adbで送るときも、`ModelCatalog.kt` のURLにあるコミットの版を取る（`hf download ... --revision <コミット>`）。版が違うと大きさが合わず、アプリはダウンロードされていないとみなす。

### モデルの版

アプリはHugging Faceのファイルを、`resolve/main/` ではなくコミットを指定したURLで取る（2026-11-08から）。モデルを配るときの一般的なやり方で、ダウンロードしたものはハッシュで照合する。C#で言えば、NuGetのパッケージを `*` ではなく版番号で固定し、ロックファイルのハッシュで照合するのに近い。

- **固定した理由**：配布元は公開後もファイルを差し替える。pfnetは2026-11-06〜11-08にGGUFのチャットテンプレートを4回更新し、そのたびに大きさとハッシュが変わった。漫画用OCRは置き場所を変え、`main` の旧パスは404になった。アプリは `main` を指したまま大きさとハッシュを持っていたので、15T Proで0.8Bのダウンロードが毎回580MBあたりで失敗した（受け取った大きさが想定を超えた）。
- **今の版（2026-11-08）**：翻訳モデルは最新のコミット（0.8B `e10c327b`、2B `d44589ec`）。更新はチャットテンプレート（GGUFの付属情報）だけで、重みは変わっていない。開発で使ってきた旧版と、ファイルの末尾4MB（重みの部分）のハッシュが一致した。アプリはチャットテンプレートを使わず、PFML3のプロンプトを自分で組み立てているので、訳は変わらない。初版の0.8B（`03891e90`）はもう取れない（403）。SenseVoiceは `2365baea`、漫画用OCRは `de0e793d`。
- **版を上げるとき**：何が変わったかをコミットの履歴で見る。重みが変わったなら、品質と速度を測り直す（`docs/03_翻訳コア.md`）。そのうえでコミット・大きさ・ハッシュをまとめて書き換え、アプリの版も上げる。大きさとハッシュはHEADの応答（`X-Linked-Size`、`X-Linked-ETag`）で取れる。
- **固定しても残る危うさ**：配布元が古いコミットのファイルを消すと、固定したURLでも取れなくなる（0.8Bの初版がそうなった）。そのときはアプリが「ダウンロードに失敗しました（HTTP 403）」などを出すので、上の手順で版を上げる。どうしても止めたくなければ、自分の置き場（GitHubのリリースなど）に写しを置く方法があるが、ライセンスの条件の確認と置き場の管理が要るので、今はしない。
- **端末に残った途中のファイル**：版を上げる前の `.part` が残っていると、続きから取っても照合が合わない。そのときは自動で最初から取り直す。受け取った大きさが想定を超えたら、途中のファイルを捨てて「ダウンロード元のファイルが想定と違います」を出す。

漫画用OCRは、配布元の次のファイル（FP16版ではなく通常版）を取得し、名前を変えて `models/ocr/manga/` に置く。

## ビルドと実行

2026-11-05時点はAndroid Studioを使わず、コマンドでビルドして入れている（PowerShell）。

```powershell
$env:JAVA_HOME="$env:LOCALAPPDATA\Programs\jdk-21"
./tools/get-sherpa-onnx.ps1   # 初回だけ。sherpa-onnxのAARを third_party/sherpa-onnx/ に取得する
.\gradlew.bat :core-llm:testDebugUnitTest :core-ocr:testDebugUnitTest :core-asr:testDebugUnitTest :app:testDebugUnitTest :app:installDebug
```

- sherpa-onnxのAARが無いとビルドが失敗する。AARはGitに入れていないので、新しいPCでは先に `get-sherpa-onnx.ps1` を実行する。

- 初回はGradle本体・ライブラリの取得とllama.cppのコンパイルで数分かかる。`local.properties` に `sdk.dir` を書いておく（Gitの対象外）。
- デバッグビルドでもllama.cppは `-DCMAKE_BUILD_TYPE=Release` で最適化してビルドする（`core-llm/build.gradle.kts`）。
- ユーザー環境変数 `PYTHONUTF8=1` が要る。llama.cppのOpenCLカーネルを埋め込むPythonスクリプトが、日本語環境の既定（cp932）だとソースを読めずに失敗する（2026-11-05）。
- `jvmToolchain(17)` は使わない。JDK 21でビルドし、出力だけJava 17相当にしている（JDK 17を入れていないため）。
- モデルはアプリを一度起動してから置く（アプリのフォルダーができる）。

- ログは `adb logcat -s PlamoTranslate` で見る。各モジュールのタグは `PlamoTranslate` にそろえる。翻訳ごとに `翻訳: プロンプト N トークン …ms、生成 …` の行が出る。
- REDMAGIC（ZTE系）は `log.tag=S` で全ログを抑止している。見えないときは `adb shell setprop log.tag.PlamoTranslate V` を実行する（端末の再起動で戻る）。
- 翻訳はQualcommの端末ではGPU、それ以外はCPUで動く（`docs/02_アーキテクチャ.md`「GPUとCPUの切り替え」）。この端末でCPUの速さを確かめるときは、設定の画面の「パフォーマンス」で「CPUだけで動かす」を選んで起動し直す。トップ画面右上（「2B・GPU ⚙」など）、会話・カメラ・テキストの画面の切り替えボタン、設定の画面に、GPUとCPUのどちらで動いているかが出る。
- 計測用の画面は `app` のデバッグビルドだけに入れる。デバッグビルドでは、画面翻訳を開始した状態で、PCから `adb shell am broadcast -a app.plamotranslate.DEBUG_TRANSLATE` を送ると画面翻訳を1回動かせる。`DEBUG_CONFIG`（`--ez boost false --ei threads 6`）で性能ヒントとスレッド数を切り替えられる（計測用）。

## 配布用のAPK

配布する正式版（リリース版）は、作者が作った鍵で署名し、GitHubのリリース（Releases）にAPKを置いて配る（2026-11-08から）。

```powershell
$env:PYTHONUTF8="1"
.\gradlew.bat :app:assembleRelease
# できるもの：app/build/outputs/apk/release/app-release.apk（約85MB）
# 配る用に版番号（versionName）を付けて控える（dist/ はGitに入れない）
Copy-Item app/build/outputs/apk/release/app-release.apk dist/PlamoTranslate-<versionName>.apk
```

版を上げるときは `app/build.gradle.kts` の `versionCode`（整数、毎回1つ上げる）と `versionName` を変える。`versionCode` が上がっていないと、配った端末で上書きできない。リリースのタグは `v<versionName>`（例：`v0.3.4`）とし、APKの名前は `PlamoTranslate-<versionName>.apk` にする。最初に公開した版は0.3.4。

- **署名鍵**：鍵（`.jks`）と、パスワードなどを書いた `keystore.properties` は、リポジトリの外の安全な場所に置き、Gitに入れない。`keystore.properties` には `storeFile`・`storePassword`・`keyAlias`・`keyPassword` を書く（`storeFile` は相対パスなら `keystore.properties` のフォルダーから探す）。各PCの `local.properties`（Git対象外）に `plamo.keystore=<そのフォルダー>/keystore.properties` を1行書く（区切りは `/`。日本語のパスならUTF-8で保存する）。`app/build.gradle.kts` がこれを読み、無ければ署名しない（`app-release-unsigned.apk` になり、端末に入らない）。自分でビルドする場合は、自分の鍵を作って同じように指定する。
- **鍵を失わない**：同じ鍵で署名した新しい版なら、入れた端末で上書きの更新ができる。鍵を失うと、使っている人はアプリを消して入れ直すしかなく、ダウンロードしたモデルも消える。鍵のフォルダーは別の場所にも控えを取っておく。
- **開発版との関係**：開発版（`installDebug`）はPCごとのデバッグ用の鍵で署名されている。開発版が入っている端末に正式版を入れるには、一度アプリを消す必要がある（モデルも消えるので、入れ直したらダウンロードし直す）。
- **入っていないもの**：正式版には、評価用の `BenchActivity`、翻訳モデルの比べの `TranslateBenchActivity`、adbから音声ファイルを流す会話翻訳の入口は入らない（`app/src/debug/` だけにある）。デバッグもできない。

使う人の手順：

1. リリースのページからAPKのファイルを端末にダウンロードする。
2. ファイルを開き、「提供元不明のアプリのインストール」を、開いたアプリに許可する。
3. インストールしてアプリを開き、最初に出る「モデルの準備」の画面で「ダウンロード」を押す（約836MB。Wi-Fiで）。翻訳モデルはPLaMo Community Licenseのもとで使う（画面の「ライセンスを読む」）。
4. 画面翻訳は「他のアプリの上に重ねて表示」と画面共有、会話翻訳はマイク、カメラ翻訳はカメラの許可を、使うときに求められる。
5. 翻訳モデルの2Bを使うときは、設定の画面（トップ画面右上の「0.8B・GPU ⚙」など）で「2Bをダウンロード」を押す（約1.8GB。Wi-Fiで）。
6. 新しい版は、設定の画面の「このアプリについて」で「更新を確認」→「ダウンロードして更新」を押して入れる（下の「アプリの更新」）。

### アプリの更新

正式版は、GitHubの最新のリリースから自分で新しい版を取って入れ替えられる（2026-11-09、作者の要望。`update/AppUpdater.kt`）。

- **いつ通信するか**：設定の画面で「更新を確認」「ダウンロードして更新」を押したときだけ。起動時に勝手には確かめない（翻訳・認識は通信しない、というこのアプリの約束を崩さないため）。
- **確認**：`https://api.github.com/repos/kagerouttepaso/PlamoTranslate/releases/latest` を読み、タグ（`v0.4.0`）とアプリの `versionName` を数字で比べる（`update/AppVersion.kt`）。認証は要らない（同じIPから1時間に60回まで）。
- **ダウンロードと照合**：リリースの `.apk` のアセットを、モデルと同じ部品（`ModelDownloads.download`：続きから取る、SHA-256で照合）でアプリのキャッシュ（`cacheDir/updates/`）へ取る。SHA-256はGitHubがアセットに付ける `digest` を使う。さらに、パッケージ名が同じこと、`versionCode` が今より大きいこと、署名の鍵が入っているアプリと同じことを確かめてから入れる。開発版（デバッグ鍵）には正式版で上書きできないので、ここで止まる。
- **インストール**：`PackageInstaller` のセッションで入れる（権限 `REQUEST_INSTALL_PACKAGES`）。初回は「不明なアプリのインストール」の設定を開いて許可してもらい、毎回Androidの確認画面で「更新」を押してもらう。同じ鍵の上書きなので、設定もモデルも消えない。結果は `update/InstallResultReceiver.kt` が受け取る。
- **リリースを作る側の決まり**：タグは `v<versionName>`（数字と `.` だけ。`-beta` などの後ろは比べない）、`versionCode` は必ず上げる、APKのアセットは1つだけ置く（`.apk` を最初に見つけたものを使う）、配布用の鍵で署名する。
- **Google Playで配る場合**：Playの規約で、アプリが自分を更新することは禁じられている。Playに出す版ではこの機能を外す。

## 画面翻訳の評価

`tools/run-bench.ps1` で、保存したスクリーンショットに画面翻訳と同じ処理をかけて採点する。方法と観点は `docs/05_画面翻訳.md`「評価」。採点（`tools/eval-screen.py`）にはPython 3が要り、ユーザー環境変数 `PYTHONUTF8=1` を前提にする。

英語の合成画面は `./tools/make-en-screen.ps1` で作る（既定の出力は `tools/testdata/ocr/en-synthetic/`、`truth.json` も作る）。

漫画用OCRなどの候補をPCで試す `tools/ocr-spike.py` は、ONNX Runtime・OpenCV・pyclipperを入れたPython環境で動かす（例：`%LOCALAPPDATA%\plamo-ocr-venv`）。

## 端末の片付け

区切りの終わりに、試作の残りを消し、最新のアプリとモデルだけを残す（2026-11-06、作者の依頼）。

| 場所 | 扱い |
| --- | --- |

| `/sdcard/Android/data/app.plamotranslate/files/asr-test/` | 会話翻訳の動作確認の試験音声。消す（`docs/04_会話翻訳.md`「動作確認の方法」） |
