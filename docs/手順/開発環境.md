# 開発環境

WindowsのPCでコマンドからビルドし、adbで端末に入れて試す。新しいPCでは、JDK 21・Android SDK・Python 3を入れ、リポジトリをサブモジュールごと取り、sherpa-onnxのAARを取ってからビルドする。モデルはアプリが初回起動時に取るので、PCから送るのは開発中に同じ版を置き直すときだけである。正式版は配布用の鍵で署名してGitHubのリリースに置き、アプリはそこから自分を更新する。端末に送った試作の残りは、作業の区切りで消す。

## PCに入れるもの

| ソフト | 版 | 用途 |
| --- | --- | --- |
| JDK | 21 | Gradleの実行。`core-pipeline` が `jvmToolchain(21)` を指定し、toolchainを自動で取る設定は無いので、手元に要る。出力は全モジュールJava 17相当。Android Studio同梱のJBR 25ではGradle 8.14.3が動かない |
| Android SDK Platform | API 36 | `compileSdk`・`targetSdk` |
| NDK | `29.0.14206865` | llama.cppとJNI。`core-llm/build.gradle.kts` の `ndkVersion` で固定している |
| CMake | `3.31.6`（Ninja同梱） | ネイティブビルド。`core-llm/build.gradle.kts` で固定している |
| Git | 最新 | サブモジュール（llama.cpp、OpenCL-Headers、OpenCL-ICD-Loader） |
| PowerShell | 7 以上（`pwsh`） | `tools/` のスクリプト、文書の検査と設計の点検（コミットの前と Claude Code のフックが呼ぶ） |
| Python 3 | 3系 | 必須。llama.cppのOpenCLカーネルを埋め込むスクリプトがビルド中に動く。評価の採点（`tools/eval-screen.py`）とモデルの取得（`huggingface_hub` の `hf`）にも使う |
| GitHub CLI（`gh`） | 任意 | リリースの作成とAPKの添付（「リリースを作る」）。無ければ、APKの添付と公開は作者が行う |

1. SDKの部品を入れる。Android Studioがあれば SDK Manager で入れる。無ければ Android SDK コマンドラインツールを `%LOCALAPPDATA%\Android\Sdk\cmdline-tools\latest` へ展開し、`sdkmanager` で `platform-tools`・`platforms;android-36`・`build-tools`・`ndk;29.0.14206865`・`cmake;3.31.6` を入れる。PowerShellから `sdkmanager.bat` を呼ぶときは、`'"ndk;29.0.14206865"'` のように引用符ごと渡す（cmdが `;` で引数を割り、「Package ndk not found」になる）。
2. SDKは `%LOCALAPPDATA%\Android\Sdk` に置く。`tools/` のスクリプトはadbをこの場所から呼ぶ。
3. ユーザー環境変数に `JAVA_HOME`（JDK 21の場所）、`ANDROID_HOME`（1のSDKの場所）、`PYTHONUTF8=1` を設定し、`platform-tools` を `PATH` に足す。GradleはSDKを `ANDROID_HOME` から見つけるので、`local.properties` に `sdk.dir` を書かなくてよい（Android Studioで開くと書き足されるが、どちらでも動く）。`PYTHONUTF8` が無いと、OpenCLカーネルを埋め込むスクリプトが日本語環境の既定（cp932）でソースを読めずに失敗する。
4. TLS検査のあるネットワークで `PKIX path building failed` になるときは、JavaにWindowsの証明書ストアを使わせる。`sdkmanager` は `$env:SDKMANAGER_OPTS="-Djavax.net.ssl.trustStoreType=Windows-ROOT"` を付けて動かし、Gradleは `%USERPROFILE%\.gradle\gradle.properties` に `systemProp.javax.net.ssl.trustStoreType=Windows-ROOT` を書く。プロキシを通るときは、同じファイルに `systemProp.https.proxyHost`・`systemProp.https.proxyPort` を書き、`hf` には環境変数 `HTTPS_PROXY` を設定する。

## 端末の準備

開発者向けオプションで「USBデバッグ」を有効にし、USBでつなぐ。無線なら「ワイヤレスデバッグ」の「ペア設定コードによるデバイスのペア設定」の値で `adb pair <IP>:<ペア設定用ポート>`、`adb connect <IP>:<接続用ポート>` を実行する。Wi-Fiが端末どうしの通信を遮るなら、USBを使う。

## リポジトリ

リポジトリは GitHub の [kagerouttepaso/PlamoTranslate](https://github.com/kagerouttepaso/PlamoTranslate)（ブランチ `main`）にある。公開リポジトリなので、コミットの作者はGitHubのnoreplyのアドレスにする。

1. サブモジュールごとクローンする。

   ```powershell
   git clone --recurse-submodules https://github.com/kagerouttepaso/PlamoTranslate.git
   cd PlamoTranslate
   ```

2. コミットの作者をクローンごとに設定する。Gitはリポジトリの中のファイルから設定を読まないので、クローンするたびに行う。クローンごとの設定（`.git/config`）はPCのグローバル設定より優先される。

   ```powershell
   git config user.name kagerouttepaso
   git config user.email 4670521+kagerouttepaso@users.noreply.github.com
   git config --show-origin user.email   # file:.git/config と出ればよい
   ```

3. コミットの前の検査を有効にする。`.githooks/pre-commit` が文書の検査と設計の点検を回し、誤りがあればコミットを止める（`CLAUDE.md`「規則を支える仕組み」）。これもクローンごとの設定である。

   ```powershell
   git config core.hooksPath .githooks
   ```

4. Gitに入れていないsherpa-onnxのAARを取る（無いとビルドが失敗する）。音声認識のモデルもPCに取るなら `-Models` を付ける。

   ```powershell
   ./tools/get-sherpa-onnx.ps1
   ```

5. 作業を始めるたびに `git pull` し、サブモジュールの固定したコミットが変わっていれば `git submodule update --init` で合わせる。

## ビルドと実行

テストを流してから開発版を入れる。

```powershell
.\gradlew.bat :core-pipeline:test :core-llm:testDebugUnitTest :core-ocr:testDebugUnitTest :core-asr:testDebugUnitTest :core-tts:testDebugUnitTest :app:testDebugUnitTest
.\gradlew.bat :app:installDebug
.\gradlew.bat :featurelab:installDebug   # 機能テストをするときだけ（docs/資料/端末の能力.md）
```

- `core-pipeline` はKotlin/JVMのモジュールなので、テストのタスクは `test` である。状態遷移・判定器・翻訳の契約の単体テストはここにある。ほかのモジュールはAndroidのモジュールなので `testDebugUnitTest` になる。
- 初回はGradle・ライブラリの取得と、llama.cppのコンパイルで数分かかる。llama.cppの構成時にKleidiAIを取るので、ネットにつながっている必要がある。デバッグビルドでも、llama.cppは `-DCMAKE_BUILD_TYPE=Release` で作る（Debugだと推論が桁違いに遅い）。
- 入れた直後は、アプリが「モデルの準備」の画面を出す（「モデルの取得と置き場」）。
- 開発版はPCごとのデバッグ用の鍵（`%USERPROFILE%\.android\debug.keystore`）で署名される。別のPCで入れた開発版には上書きできない（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）。複数のPCから入れるなら、同じ `debug.keystore` を各PCの同じ場所へ写す（Gitには入れない）。写さずに入れ直すとアプリのデータ（設定・モデル）が消えるので、`adb uninstall` の前に作者に確認する。

### ログを見る

1. `adb shell setprop log.tag.PlamoTranslate V` でアプリのタグを開ける。REDMAGICは既定でログを黙らせているので、端末を再起動するたびに打ち直す（`docs/資料/端末の能力.md`「設計に効く、思わぬ事実」）。
2. `adb logcat -s PlamoTranslate` で見る。各モジュールとネイティブ（`plamo_llm.cpp`）のタグは `PlamoTranslate` にそろえている。翻訳エンジンは1回の実行ごとに `翻訳（同時N本）: N件、プロンプト … トークン、生成 … トークン、…ms` の行を出す（読み方は `docs/設計/翻訳コア.md`「速さの確かめ方」）。

### GPUとCPU、デバッグ版の入口

- 翻訳はQualcommの端末ではGPU、それ以外ではCPUで動く。GPUの端末でCPUの速さを見るときは、設定の画面の「パフォーマンス」で「CPUだけで動かす」を選び、アプリを起動し直す。どちらで動いているかは、トップ画面右上（「2B・GPU ⚙」など）と設定の画面に出る。
- デバッグ版だけ、画面翻訳を開始した状態で、PCからブロードキャストで操作できる（計測用）。

  ```text
  adb shell am broadcast -a app.plamotranslate.DEBUG_TRANSLATE                                # 画面翻訳を1回動かす
  adb shell am broadcast -a app.plamotranslate.DEBUG_CONFIG --ez boost false --ei threads 6   # 性能ヒントとスレッド数を変える
  ```

- 評価の `BenchActivity` は `docs/設計/画面翻訳.md`「評価」、翻訳モデルの比べの `TranslateBenchActivity` は `docs/設計/翻訳コア.md`「モデルの比べ方」、会話翻訳に音声ファイルを流す入口は `docs/設計/会話翻訳.md`「動作確認」を見る。

## モデルの取得と置き場

アプリは初回起動時に、全画面の「モデルの準備」で要るモデルをダウンロードする。取得元のURL・大きさ・SHA-256の正本は `app/src/main/java/app/plamotranslate/models/ModelCatalog.kt`、使っている版の一覧は `docs/現在地.md`「固定した版」である。配った端末ではこれだけでよい。

開発中にPCから送るときは、`ModelCatalog.kt` のURLと同じコミットの版を送る。アプリはファイルの大きさが `ModelCatalog.kt` と一致するものをダウンロード済みとみなすので、版が違うと取り直す。Hugging Faceから取る `hf` は `pip install -U huggingface_hub` で入る。

| モデル | PCへの取り方 | 端末の置き場（`/sdcard/Android/data/app.plamotranslate/files/models/` の下） |
| --- | --- | --- |
| 翻訳 0.8B（既定） | `hf download pfnet/plamo-3-translate-0.8b-GGUF plamo-3-translate-0.8b-Q4_K_M.gguf --revision <コミット> --local-dir models` | `llm/plamo-3-translate-0.8b-Q4_K_M.gguf` |
| 翻訳 2B（選んだときだけ） | 同じく `pfnet/plamo-3-translate-2b-GGUF` の `plamo-3-translate-2b-Q4_K_M.gguf`。ふだんは設定の画面の「2Bをダウンロード」で取る | `llm/plamo-3-translate-2b-Q4_K_M.gguf` |
| 音声認識（SenseVoice Small int8、Silero VAD） | `./tools/get-sherpa-onnx.ps1 -Models` で `models/asr/` に取る | `asr/sense-voice/model.int8.onnx`・`asr/sense-voice/tokens.txt`・`asr/silero_vad.onnx` |
| 漫画用OCR（PP-OCRv6 manga） | `hf download Kellenok/PP-OCRv6_manga det/manga_det_v0.2.onnx rec/manga_rec_v0.2.onnx ppocrv6_dict.txt --revision <コミット> --local-dir models/ocr/manga-src` で取り、下の手順2で名前を変えて `models/ocr/manga/` に置く | `ocr/manga/det.onnx`・`rec.onnx`・`dict.txt` |
| 韓国語の文字の認識（PP-OCRv5 korean） | `hf download mxaln/docscanner-ocr korean/rec_model.onnx korean/charset.json --revision <コミット> --local-dir models/ocr/korean-src` で取り、下の手順2で名前を変えて `models/ocr/korean/` に置く。検出は漫画用OCRの `det.onnx` を使う | `ocr/korean/rec.onnx`・`dict.json` |
| 読み上げ（Supertonic 3） | PCからは送らない。設定の画面で選んだときにアプリが取る | `tts/supertonic-3/` |
| ML Kit | APKに同梱 | 不要 |

1. アプリを一度起動する（端末にアプリのフォルダーができる）。
2. 上の表のとおりPCに取る。`<コミット>` は `ModelCatalog.kt` のURLの `resolve/` の後ろの値。漫画用OCRと韓国語の文字の認識は、アプリが読む名前に変えて置く。

   ```powershell
   New-Item -ItemType Directory -Force models/ocr/manga | Out-Null
   Copy-Item models/ocr/manga-src/det/manga_det_v0.2.onnx models/ocr/manga/det.onnx
   Copy-Item models/ocr/manga-src/rec/manga_rec_v0.2.onnx models/ocr/manga/rec.onnx
   Copy-Item models/ocr/manga-src/ppocrv6_dict.txt models/ocr/manga/dict.txt
   New-Item -ItemType Directory -Force models/ocr/korean | Out-Null
   Copy-Item models/ocr/korean-src/korean/rec_model.onnx models/ocr/korean/rec.onnx
   Copy-Item models/ocr/korean-src/korean/charset.json models/ocr/korean/dict.json
   ```

3. adbで送る。

```text
adb push models/plamo-3-translate-0.8b-Q4_K_M.gguf /sdcard/Android/data/app.plamotranslate/files/models/llm/
adb push models/ocr/manga/. /sdcard/Android/data/app.plamotranslate/files/models/ocr/manga/
adb push models/ocr/korean/. /sdcard/Android/data/app.plamotranslate/files/models/ocr/korean/
adb push models/asr/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17/model.int8.onnx /sdcard/Android/data/app.plamotranslate/files/models/asr/sense-voice/
adb push models/asr/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17/tokens.txt /sdcard/Android/data/app.plamotranslate/files/models/asr/sense-voice/
adb push models/asr/silero_vad.onnx /sdcard/Android/data/app.plamotranslate/files/models/asr/
```

PCの `models/plamo-3-translate-0.8b-Q4_K_M.gguf` は端末のCLIの計測（`tools/device-translate.ps1`）が、`models/ocr/manga/`・`models/ocr/korean/` はPCでの文字認識の試作（`tools/ocr-spike.py`）も使う。

### モデルの版を上げる

アプリはHugging Faceのファイルを、コミットを指定したURLで取り、大きさとSHA-256で照合する（理由は `docs/判断/2026-11-08_モデルのURLをコミットで固定し大きさとハッシュで照合する.md`）。配布元が古いコミットのファイルを消すと、アプリは「ダウンロードに失敗しました（HTTP 403）」などを出すので、次の手順で版を上げる。

1. 配布元のコミットの履歴で、何が変わったかを見る。
2. 重みが変わったなら、品質と速度を測り直す（`docs/設計/翻訳コア.md`）。
3. 新しいコミットの大きさとハッシュを、HEADの応答の `X-Linked-Size`（バイト数）と `X-Linked-ETag`（SHA-256）で取る。`curl.exe -sI <新しいURL>` で見る（転送先へ進まない最初の応答に付く）。
4. `ModelCatalog.kt` のURL・大きさ・SHA-256をまとめて書き換え、`docs/現在地.md`「固定した版」を直し、アプリの版を上げる。

## 端末でCLIを動かして測る

llama.cppのCLIを端末で直接動かすと、アプリの外で端末の素の速さを測れる（アプリ内の速さと比べるときに使う。`docs/設計/翻訳コア.md`「速さの確かめ方」）。

1. SDK同梱のCMake・Ninjaで、CPU版のCLIを `build-android/` に作る。

   ```powershell
   $s="$env:LOCALAPPDATA\Android\Sdk"; $cm="$s\cmake\3.31.6\bin"
   & "$cm\cmake.exe" -S third_party/llama.cpp -B build-android -G Ninja "-DCMAKE_MAKE_PROGRAM=$cm\ninja.exe" `
     "-DCMAKE_TOOLCHAIN_FILE=$s/ndk/29.0.14206865/build/cmake/android.toolchain.cmake" `
     -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-28 -DCMAKE_BUILD_TYPE=Release `
     -DGGML_NATIVE=OFF -DGGML_OPENMP=OFF -DGGML_LLAMAFILE=OFF -DLLAMA_OPENSSL=OFF `
     -DGGML_CPU_KLEIDIAI=ON -DBUILD_SHARED_LIBS=OFF -DLLAMA_BUILD_TESTS=OFF
   & "$cm\cmake.exe" --build build-android -j 12 --target llama-cli llama-bench llama-completion
   ```

2. 翻訳モデルを `models/plamo-3-translate-0.8b-Q4_K_M.gguf` に置く（「モデルの取得と置き場」）。
3. `./tools/device-translate.ps1 -Text "<原文>" -Source ko -Target ja` で1文を訳し、`./tools/device-translate.ps1 -Bench` で `llama-bench` を動かす。CLIとモデルは端末の `/data/local/tmp/plamo/` へ送られる。
4. GPU（OpenCL）で測るときは、まずリンク用の `libOpenCL.so`（KhronosのICDローダー）を同じツールチェーンで作る。アプリのビルドが `core-llm/src/main/cpp/CMakeLists.txt` で作るものと同じ設定である。実行時は端末の `/vendor/lib64/libOpenCL.so` を使うので、作ったものは端末へ送らない。

   ```powershell
   $s="$env:LOCALAPPDATA\Android\Sdk"; $cm="$s\cmake\3.31.6\bin"
   & "$cm\cmake.exe" -S third_party/OpenCL-ICD-Loader -B build-android/opencl-icd -G Ninja "-DCMAKE_MAKE_PROGRAM=$cm\ninja.exe" `
     "-DCMAKE_TOOLCHAIN_FILE=$s/ndk/29.0.14206865/build/cmake/android.toolchain.cmake" `
     -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-28 -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=OFF `
     "-DOPENCL_ICD_LOADER_HEADERS_DIR=$PWD/third_party/OpenCL-Headers"
   & "$cm\cmake.exe" --build build-android/opencl-icd --target OpenCL
   ```

   次に、1の構成に `-DGGML_OPENCL=ON`、`"-DOpenCL_INCLUDE_DIR=$PWD/third_party/OpenCL-Headers"`、`"-DOpenCL_LIBRARY=$PWD/build-android/opencl-icd/libOpenCL.so"` を足して作り直す。端末では `LD_LIBRARY_PATH=/vendor/lib64` を付けて動かす。
5. 測り終えたら消す（「端末の片付け」）。

## 画面翻訳の評価

保存したスクリーンショットに、デバッグ版の `BenchActivity` で画面翻訳と同じ処理をかけて採点する。観点と採点の方法は `docs/設計/画面翻訳.md`「評価」。

1. 評価用の画像は著作物を含むのでGitに入れない。手元に無ければ作者にスクリーンショットを頼み、正解（`truth.json`）も作り直す。画像と `truth.json` は `tools/testdata/ocr/<セット>/` に置く。
2. 開発版を入れた端末で `./tools/run-bench.ps1 -Set <セット> -Label <名前>` を流す（原文の言語は `-Lang AUTO|CHINESE|KOREAN|LATIN`）。画像を端末の `files/bench/in` へ送り、結果を `tools/testdata/ocr/<セット>-out/<名前>/` へ取り出し、`truth.json` があれば `tools/eval-screen.py` で採点する。
3. 変更の前と後で同じセットを流して比べる。

- 英語の合成画面と正解は `./tools/make-en-screen.ps1` で作る（既定の出力は `tools/testdata/ocr/en-synthetic/`）。
- 文字認識の候補をPCで試す `tools/ocr-spike.py` は、ONNX Runtime・OpenCV・pyclipperを入れたPythonの仮想環境で動かす。

## 配布用のAPK

正式版は配布用の鍵で署名し、GitHubのリリースにAPKを1つ置いて配る（`docs/判断/2026-11-08_署名したAPKをGitHubのリリースで配る.md`）。正式版には `app/src/debug/` の入口（`BenchActivity`、`TranslateBenchActivity`、会話翻訳に音声ファイルを流す入口、デバッグのブロードキャスト）が入らない。

### 署名鍵を用意する

1. 鍵（`.jks`）と、`storeFile`・`storePassword`・`keyAlias`・`keyPassword` を書いた `keystore.properties` を、リポジトリの外の安全な場所に置く。`storeFile` が相対パスなら、`keystore.properties` のフォルダーから探す。
2. 各PCの `local.properties` に `plamo.keystore=<そのフォルダー>/keystore.properties` を1行書く（区切りは `/`。日本語のパスならUTF-8で保存する）。`app/build.gradle.kts` がこれを読む。無ければ署名せず、`app-release-unsigned.apk` になる（端末に入らない）。
3. 鍵のフォルダーは別の場所にも控える。鍵を失うと、使う人はアプリを消して入れ直すしかなく、モデルも消える。

### リリースを作る

1. 前の版のタグからの差分を、`design-reviewer` エージェントで点検する（`change-flow` スキル「リリースの前」）。直すべき構造の崩れは、この版で直すか `docs/バックログ.md` の「リファクタリング」に理由と一緒に置く。
2. 依存やモデルを変えたなら、「ライセンス文を集め直す」を行う。`app/build.gradle.kts` の `versionCode` を1つ上げ、`versionName` を変える。`versionCode` が上がっていないと、配った端末で上書きできない。
3. 正式版を作り、版番号を付けて `dist/`（Gitの対象外）に控える。

   ```powershell
   $env:PYTHONUTF8="1"
   .\gradlew.bat :app:assembleRelease
   New-Item -ItemType Directory -Force dist | Out-Null
   Copy-Item app/build/outputs/apk/release/app-release.apk dist/PlamoTranslate-<versionName>.apk
   ```

   公開する前にこの正式版を端末に入れて確かめ、その後に中身を変えたら、2に戻って版を上げてから作り直す。同じ `versionCode` で中身の違う版を公開すると、先に入れた端末はそれを新しい版として受け取れない（`docs/判断/2026-11-12_0.6.0を欠番にしv0.6.1として出す.md`）。
4. `main` と、タグ `v<versionName>` をプッシュする。タグは数字と `.` だけにする（アプリは `-beta` などの後ろを比べない）。

   ```powershell
   git tag v<versionName>
   git push origin main v<versionName>
   ```

5. GitHubのリリースを作り、APKを1つだけ添付して公開する。題名は「Mockingword <versionName>」。本文は利用者向けに「増えたこと」「変わったこと」「入れ方」「注意」の節で書き、前の版のリリースを手本にする。完了した作業の一覧の正本はこの本文なので、利用者に見える変化は漏らさず書く。「注意」にはPLaMo Community Licenseの条文のリンク（https://plamo.preferredai.jp/info/plamo-community-license-ja ）を添える。
   - GitHub CLIがあれば、次で作成・添付・公開まで行える。

     ```powershell
     gh release create v<versionName> dist/PlamoTranslate-<versionName>.apk --title "Mockingword <versionName>" --notes-file <本文のファイル> --verify-tag
     ```

   - 無ければ、APKの添付と公開は作者が行う。
6. 公開した後、最新のリリースのタグと、APKの `digest`（`sha256:` の後ろ）が、手元のAPKのSHA-256と一致することを確かめる。

   ```powershell
   $r = gh api repos/kagerouttepaso/PlamoTranslate/releases/latest | ConvertFrom-Json   # gh が無ければ Invoke-RestMethod で同じURLを読む
   $r.tag_name; $r.assets | Select-Object name, digest
   (Get-FileHash dist/PlamoTranslate-<versionName>.apk -Algorithm SHA256).Hash.ToLower()
   ```

7. `docs-update` スキルの手順で、`docs/現在地.md` の状態と次の作業を公開した後のものに書き換える。

開発版が入っている端末には、正式版を上書きできない（鍵が違う）。入れるにはアプリを消す必要があり、モデルも消えるので、作者に確認してから行う。

### ライセンス文を集め直す

アプリに同梱するライセンス文は `app/src/main/assets/licenses/` にある（`docs/設計/アーキテクチャ.md`「採用している技術」の「ライセンスの表示」）。依存の版を変えたら、リリースの前に次を行う。

1. `python tools/collect-licenses.py` を流す。正式版に入る Maven の依存の一覧（`maven.txt`）、Google のライブラリが同梱する第三者のライセンス文（`google-third-party.txt`）、ONNX Runtime の第三者の告知（`onnxruntime-third-party-notices.txt`）を作り直す。POM にライセンスの記載が無い依存が増えると止まるので、確かめて道具の `KNOWN` に足す。
2. 手で書く `native.txt` を、変えた版に合わせる。llama.cpp・KleidiAI・sherpa-onnx（静的に組み込まれた第三者のコードの版は、sherpa-onnx の `cmake/*.cmake` で分かる）・libc++・libyuv の節である。sherpa-onnx を1.x系に戻すと、GPL-3.0 の espeak-ng が入るので戻さない。
3. モデルを足したり変えたりしたら、`AboutApp.kt` の一覧（名前・作者・ライセンス名・配布元）を直す。

### 配った端末に入れる手順

リリースのノートに書く、使う人の手順である。

1. リリースのページからAPKを端末に取って開き、「提供元不明のアプリのインストール」を許可して入れる。
2. アプリを開き、「モデルの準備」の画面で「ダウンロード」を押す（大きさは画面に出る。Wi-Fiで取る）。翻訳モデルはPLaMo Community Licenseのもとで使う（画面の「ライセンスを読む」）。
3. 新しい版は、設定の画面の「このアプリについて」の「更新を確認」で入れる。

### アプリの更新

使う人は、設定の画面の「このアプリについて」で「更新を確認」を押し、新しい版があれば「ダウンロードして更新」を押して、Androidのインストールの確認に答える。アプリはそのときだけGitHubの `releases/latest` から新しい版を取る（`app/src/main/java/app/plamotranslate/update/AppUpdater.kt`）。上の「リリースを作る」の決まり（タグの形、`versionCode` を上げる、APKを1つだけ添付する）は、この仕組みが入れ替える前に確かめることから来ている。開発版が入っている端末では、鍵が違うので更新は止まる。正式版の鍵で署名した端末（versionCode 14）から0.8.0へ、この仕組みで上げられることを確かめてある。

## 端末の片付け

作業の区切りで、試作の残りを消し、最新のアプリとモデルだけを残す。

| 場所 | 扱い |
| --- | --- |
| `/data/local/tmp/plamo/`、`/data/local/tmp/llama.cpp/cl-cache/` | CLIの計測で送ったCLI・モデルと、GPUのCLIが作るカーネルの控え。消す |
| `/sdcard/Android/data/app.plamotranslate/files/bench/` | 評価の画像と結果。`run-bench.ps1` が毎回作り直すので消す |
| `/sdcard/Android/data/app.plamotranslate/files/*.tsv` | 翻訳モデルの比べに送った文の組と結果。消す |
| `/sdcard/Android/data/app.plamotranslate/files/asr-test/` | 会話翻訳の動作確認の試験音声。消す |
| `/sdcard/Android/data/app.plamotranslate.featurelab/files/lab/` | 機能テストの窓の撮影で保存した画像（作者の画面の中身）。消す |
| `/sdcard/Android/data/app.plamotranslate/files/models/` | 翻訳・音声認識・漫画用OCR・読み上げのモデル。残す |
| アプリの `cache/cl-cache/` | GPUカーネルのコンパイル結果。残す（消すと次の起動が遅くなる） |
| 機能テスト用のアプリ（`app.plamotranslate.featurelab`） | ユーザー補助の「機能テスト（合図の計測）」をオフにする。アプリを消すかは作者に確認する |
| `log.tag.FeatureLab` | 機能テストのログを出すために開けたもの。`adb shell setprop log.tag.FeatureLab '""'` で戻す（端末の再起動でも戻る） |
| アプリ本体 | `.\gradlew.bat :app:installDebug` で最新を上書きする。`adb uninstall` はモデルを含むデータも消すので、作者に確認する |

```powershell
adb shell "rm -rf /data/local/tmp/plamo /data/local/tmp/llama.cpp/cl-cache /sdcard/Android/data/app.plamotranslate/files/bench /sdcard/Android/data/app.plamotranslate/files/asr-test /sdcard/Android/data/app.plamotranslate/files/*.tsv /sdcard/Android/data/app.plamotranslate.featurelab/files/lab"
```
