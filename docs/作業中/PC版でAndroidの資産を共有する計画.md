# PC版でAndroidの資産を共有する計画

## 望む状態

- PC版は、Android版でできていることを同じ振る舞いでできる。差があってよいのは、OSの違いが理由のもの（権限、通知、カメラ、画面の撮り方）だけにする。
- 最後は、機能の振る舞いの正本を1つにし、AndroidとPCの両方がそれを使う。片方で直したことが、もう片方にも効く。

## 今の問題

PC版は、手順1・2で中核（`core-pipeline`）と翻訳エンジンだけを共有し、アプリの層（`app`）にある資産をPC用に小さく作り直した。その結果、Android版でできていたことがPC版でできない。

| 項目 | Android版 | 取り込み前のPC版 |
| --- | --- | --- |
| 翻訳モデル | `ModelCatalog` の0.8B・2Bから選ぶ。取得の進み具合を表示し、中止しても再開できる。SHA-256照合後に切り替える | GGUFファイルを指定して読み込む。一覧とダウンロードはない |
| 翻訳の実行先・性能 | GPUとCPUを選べる。GPUで落ちたときはCPUに戻す。CPUや同時に訳す数を調整できる | Vulkanを優先する。スレッド数と同時に訳す数の設定はある |
| 会話の話し手・言語 | 話した言語で話し手を判定する。相手の言語は自動か固定 | 開始前に話し手と言語を固定する |
| 会話の表示と操作 | 途中訳と確定訳、対面と1画面、手動の区切り、カードの言語の訂正、記録の書き出し、読み上げ | 途中訳と確定訳、手動の区切り。再生音を取り込む場合は別ウィンドウに字幕を出せる |
| 音声認識 | SenseVoice SmallとQwen3-ASR 0.6Bから選ぶ。認識や区切りを設定できる | Qwen3-ASRとSilero VADの組を使う。認識の設定はない |
| テキスト翻訳 | 原文の言語（自動・指定）と訳す先、入れ替え、原文の音声入力、コピー | 原文の言語（自動・指定）と訳す先、翻訳の取り消し、訳文のコピー |
| 記録の設定 | 原文・訳文を含む詳しい記録のオン・オフ。不具合の記録を書き出せる | ログを出すが、画面から詳しい記録を切り替えられない |

権限、通知、カメラ翻訳、画面翻訳は、OSの違いがあるため今回の対象外とする。再生音の字幕はPC版に残し、読み上げは速さを確かめてから扱う。

原因は、計画の「Android との共有：初めは画面を共有しない」と、モデルのダウンロードを手順4へ回した判断にある。叩き台を早く通すために、アプリの層をPC用に小さく作り直したため、Android版の作り込みが入らなかった。

## 方針

2段階で進める（作者と合意）。

1. **まねて取り込む**：`desktop` の中で、Android版の `app` の振る舞いをできる限りそのまま移す。コードは写してよい。Androidに依存する部分（`Context`・`SharedPreferences`・ファイルの置き場・`Build`・権限）だけをPCのものに置き換える。画面は共有せず、Android版の画面と同じ項目・同じ操作をそろえる。
2. **共通化する**：PC版が動いて使えるようになってから、`app` と `desktop` で同じになったコードを、Androidに依存しない共有のモジュール（Kotlin/JVM）へ移し、写しを消す。設定の保存（キーと値）・データの置き場・端末の情報を小さなインターフェースにする。モジュールの追加は、この段階で依存の表と一緒に決める。

1段階目で写すときは、2段階目で移しやすいように、Androidに依存する部分を写したコードの端に寄せる。

## 1段階目で取り込むもの（優先の順）

1. **モデルと実行先**：`ModelCatalog` の一覧（0.8B・2B）、ダウンロードとハッシュの照合（`ModelDownloads`）、モデルの切り替え、GPUとCPUの選択とGPUで落ちたときの戻し（`GpuGuard`）。
2. **会話翻訳**：マイクで、話した言語から話し手を自動で判定する（Qwen3-ASR の言語の判定を使う）。話し手を手で選ぶ形も残す。カードの入れ替え、記録の書き出し、音声認識の設定。再生音の字幕は `desktop` の機能として残す。
3. **テキスト翻訳**：言語の選択、コピー、Android版にある操作。
4. **設定**：Android版の設定の項目のうち、PCで意味があるもの。

読み上げは、計画の本体（`PC版を足す計画.md`）のとおり、速さを測ってから入れる。

## 1段階目の進み具合

- 翻訳モデルと実行先：0.8B・2Bの選択、途中からの取得、照合、読み込み直し、Vulkan と CPU の切り替えを取り込んだ。任意の GGUF の指定は「モデルの詳細」に残した。
- 会話翻訳：話者の自動判定と手動指定、相手の言語の自動・固定、対面表示、カードの話者訂正、記録の保存・コピー、音声認識の設定を取り込んだ。再生音の字幕は残した。認識モデルは手順に沿って配置し、読み上げは取り込まない。
- テキスト翻訳：言語の入れ替え、貼り付けと同時に翻訳、消去、原文・訳文のコピー、訳し直し、原文のマイク入力を取り込んだ。訳す先は PDF と共通にし、読み上げは取り込まない。
- 設定：モデル・実行先、スレッド数と同時に訳す数、音声認識、原文と訳文の詳しい記録を設定画面にまとめた。Android の録音保存と不具合の記録の ZIP 書き出しは取り込まない。
- 起動：開発用のショートカットの作り方を `docs/手順/開発環境.md`「Windows版のビルドと実行」に記した。MSI は作らない。

## 確かめること

- 永続のキャッシュ（Android は SQLite）を PC でどう持つか。
- Windows の画面でモデルのダウンロードと再開、2B への切り替え、Vulkan と CPU の切り替え、マイクでの話者判定と字幕を確かめる。性能の計測は別に行う。
- 各段階の終わりに、Androidの単体試験と `:app:assembleDebug` で Android 版が壊れていないことを確かめる（全体のビルドなので作者の指定した時間に1回）。
