# PC版でAndroidの資産を共有する計画

## 望む状態

- PC版は、Android版でできていることを同じ振る舞いでできる。差があってよいのは、OSの違いが理由のもの（権限、通知、カメラ、画面の撮り方）だけにする。
- 最後は、機能の振る舞いの正本を1つにし、AndroidとPCの両方がそれを使う。片方で直したことが、もう片方にも効く。

## 今の問題

PC版は、手順1・2で中核（`core-pipeline`）と翻訳エンジンだけを共有し、アプリの層（`app`）にある資産をPC用に小さく作り直した。その結果、Android版でできていたことがPC版でできない。

| Android版 | 今のPC版 |
| --- | --- |
| 翻訳モデルを一覧（`ModelCatalog`）から選び、0.8Bと2Bを切り替え、ダウンロードできる | GGUFのファイルを選ぶだけ。ダウンロードも切り替えの一覧も無い |
| GPUとCPUを選べ、GPUで落ちたときにCPUへ戻す（`GpuGuard`） | 選べない。Vulkanが使えればVulkan |
| 会話翻訳は、話した言語から話し手を自動で判定し、カードの向きを決める | 話し手を選んでから開始し、切り替えるには止めて選び直す |
| 会話翻訳の操作（カード、入れ替え、読み上げ、記録の書き出し） | PC用に作った簡単な画面 |
| 音声認識のモデルと設定（`SpeechPreferences`・認識の設定の画面） | 固定 |

原因は、計画の「Android との共有：初めは画面を共有しない」と、モデルのダウンロードを手順4へ回した判断にある。叩き台を早く通すために、アプリの層をPC用に小さく作り直したため、Android版の作り込みが入らなかった。

## 方針

2段階で進める（作者と合意）。

1. **まねて取り込む**：`desktop` の中で、Android版の `app` の振る舞いをできる限りそのまま移す。コードは写してよい。Androidに依存する部分（`Context`・`SharedPreferences`・ファイルの置き場・`Build`・権限）だけをPCのものに置き換える。画面は共有せず、Android版の画面と同じ項目・同じ操作をそろえる。
2. **共通化する**：PC版が動いて使えるようになってから、`app` と `desktop` で同じになったコードを、Androidに依存しない共有のモジュール（Kotlin/JVM）へ移し、写しを消す。設定の保存（キーと値）・データの置き場・端末の情報を小さなインターフェースにする。モジュールの追加は、この段階で依存の表と一緒に決める。

1段階目で写すときは、2段階目で移しやすいように、Androidに依存する部分を写したコードの端に寄せる。

## 1段階目で取り込むもの（優先の順）

1. **モデルと実行先**：`ModelCatalog` の一覧（0.8B・2B）、ダウンロードとハッシュの照合（`ModelDownloads`）、モデルの切り替え、GPUとCPUの選択とGPUで落ちたときの戻し（`GpuGuard`）。
2. **会話翻訳**：マイクで、話した言語から話し手を自動で判定する（Qwen3-ASR の言語の判定を使う）。話し手を手で選ぶ形も残す。カードの入れ替え、記録の書き出し、音声認識の設定。再生音の字幕は `desktop` の機能として残す。
3. **テキスト翻訳**：言語の選択、コピー、Android版にある操作。
4. **設定**：Android版の設定の項目のうち、PCで意味があるもの。

読み上げは、計画の本体（`PC版を足す計画.md`）のとおり、速さを測ってから入れる。

## 確かめること

- 永続のキャッシュ（Android は SQLite）を PC でどう持つか。
- 各段階の終わりに、Androidの単体試験と `:app:assembleDebug` で Android 版が壊れていないことを確かめる（全体のビルドなので作者の指定した時間に1回）。
